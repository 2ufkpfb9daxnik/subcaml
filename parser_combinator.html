4-2. 字句解析器および構文解析器の自作

文字列から抽象構文木（AST）を生成する関数 parse があれば、わざわざ If (Eq(IntLit 2, IntLit 1), ...) のように複雑な exp 型のデータを手で書く必要がなくなり、大変便利である。これまでは ocamllex や ocamlyacc などの専用ツールを利用してこれを実現することを前提としてきたが、プログラミング言語の処理系の全容を真に理解するためには、これらを自作することが有効である。

構文解析器をゼロから自作すると聞くと、複雑で難解なプログラムになると思うかもしれない。しかし、OCamlのような関数型言語の仕組みをうまく活用すれば、美しく、簡潔で、わかりやすいプログラムとして実装することができる。

文字列から構文木を組み立てる処理は、大きく分けて字句解析と構文解析の2つの役割からなる。複雑な処理に見えるが、これらを実装するには、いきなり全体を書こうとするのではなく、ごく小さな処理の単位に問題を分割し、それらを組み合わせていく手法をとればよい。

  • 字句解析器 (lexer)：入力として文字のリストを受け取り、意味のある塊（トークン）と、まだ処理していない残りの文字列のペアを出力する。
  • 構文解析器 (parser)：字句解析の結果を利用して、完成した構文木（AST）と、まだ処理していない残りの文字列のペアを出力する。

一般的な構文解析では、まず字句解析器が入力された文字列全体を読み取り、整数、識別子、予約語、演算子などからなるトークン列へ変換する。その後、構文解析器が完成したトークン列を先頭から読み取り、抽象構文木を組み立てる。つまり、字句解析と構文解析を別々の段階として実行する。 

入力文字列
  ↓ 字句解析器
トークン列
  ↓ 構文解析器
抽象構文木

一方、本章では、入力文字列全体をあらかじめトークン列へ変換しない。構文解析器が整数や演算子などを必要とするたびに、入力の先頭から対応する文字を読み取る関数を呼び出す。例えば、整数が必要な場所では int_p を呼び、予約語が必要な場所では keyword_p を呼び、記号が必要な場所では symbol_p を呼ぶ。 

入力文字列
  ↓
構文解析器が必要な字句を一つ読み取る
  ↓
読み取った結果を使って構文木の一部を作る
  ↓
残りの入力について同じ処理を続ける

したがって、本章の int_p、keyword_p、symbol_p などは、入力全体をトークン列へ変換する独立した字句解析器ではなく、構文解析器の内部から必要に応じて呼び出される字句解析の部品である。字句を一つ読み取る処理と構文木を組み立てる処理を交互に進めることで、中間的なトークン列を作らずに、入力文字列から直接抽象構文木を構築する。

字句解析器 (lexer) の実装方針

字句解析器は、入力された文字列をトークン（単語に相当する意味の塊）の列に分割する役割を持つ。これを実装するためには、以下のように小さな関数へと問題を分割する。
  • 入力文字列を文字のリストに変換する: 外部から与えられる string を、先頭と残りに分けやすい char list に変換する。
  • 1文字を処理する: 入力された文字列の先頭から、条件に合う「1文字」だけを読み取る機能を作る。
  • 不要な文字を読み飛ばす: 上記を利用して、スペースや改行などの意味を持たない空白文字を連続して読み飛ばす機能を作る。
  • 意味のある塊（トークン）を切り出す: 数字が連続していれば束ねて「整数」に変換し、+ や * といった文字が来れば「特定のキーワードや記号」として認識して切り出す機能を作る。

ただし、前述の通り、本章の実装では、独立したトークン列を先にすべて作るのではなく、整数やキーワードを入力の先頭から切り出す小さな字句解析の関数を、構文解析器から直接呼び出す。したがって、以下で作成する int_p や keyword_p などは、構文解析器の内部で利用する字句解析の部品として位置付ける。

1. 字句解析器（lexer）の実装

字句解析器は、入力された文字のリスト（char list）を受け取り、意味のあるデータ（トークン）と残りの文字列のペアを返す。ここではAST（構文木）の構築はまだ行わず、あくまで「文字の列からトークンを切り出す」ことだけに専念する。

最初に、対象とするミニOCaml言語の式の構文を限定して、「整数の定数」と「足し算」「かけ算」だけを持つ式とし、これに対する字句解析および構文解析を考える。したがって、現段階の処理系には if 式や真偽値定数などは含まないことに注意してほしい。まずはこの限定された構文に対して「文字列から構文木を完全に構築する」という一連の流れを完成させる。それが完了したその後から、徐々に機能を足していくことにする。

これを簡単に実装するために、先ほどの4つの処理（サブ目標）を、さらに具体的な「ミニ目標」に分割してコードを記述していく。

サブ目標 1: 入力文字列を文字のリストに変換する

字句解析器が受け取る元のソースコードは、 "1 + 2" のような string 型の文字列である。 OCamlでは String.get s i または s.[i] によって文字を取り出せるが、添字を使う方法では 「現在何文字目まで読んだか」も管理する必要がある。

本章では、先頭の文字と未処理の残りを c :: cs によって直接分けられるよう、 パーサの入力を char list として扱う。

その実現のために、まず、string型として受け取ったソースコードを、一度、sequence型という「文字を順番に取り出せる列」に変換し、さらにそれを char list に変換することで、サブ目標1を達成する。

シーケンスは、リストと同じように、 要素を先頭から順番に扱うためのデータである。 両者は構造もよく似ており、 どちらも「先頭の要素」と「その後ろに続く部分」からなる。

違いは、後ろに続く部分の持ち方にある。 リストでは、後ろに続く部分もすでに作られたリストである。 一方、シーケンスでは、後ろに続く部分を直接持つ代わりに、 それを必要になったときに返す関数を持っている。 

リスト:
先頭の要素 ＋ 残りのリスト

シーケンス:
先頭の要素 ＋ 残りを返す関数

ただし、今回この違いを詳しく利用するわけではない。 OCamlの標準ライブラリには、 文字列を直接 char list に変換する関数がないため、 文字列とリストの両方が変換に対応している Seq.t を中間の形式として使用する。 

string
  ↓ String.to_seq
char Seq.t
  ↓ List.of_seq
char list

    char list に input という名前を付ける。
  • ミニ目標 1-2: 文字列を文字の列へ変換する
    String.to_seq を使って、 文字列に含まれる文字を先頭から順番に取り出せる列を作る。
  • ミニ目標 1-3: 文字の列をリストへ変換する
    List.of_seq を使って、 文字の列を char list に変換する。
ミニ目標 1-1: input の型定義
(* input は、まだ読み取っていない文字のリストを表す *)
type input = char list
ミニ目標 1-2: String.to_seq による文字の列への変換

String.to_seq は、文字列を受け取り、 その文字列に含まれる文字を先頭から順番に取り出せる シーケンスを返す関数である。 

(* String.to_seq : string -> char Seq.t *)

例えば、次の式を考える。 

String.to_seq "abc"

この式は、'a'、'b'、'c' をこの順番で取り出せるシーケンスを返す。 結果の型は char list ではなく、 char Seq.t である。

Seq.t は、要素を最初からすべて格納するリストとは異なり、 必要になったときに次の要素を取り出すための列を表す。 そのため、OCamlの対話環境でシーケンスをそのまま表示すると、 関数を表す <fun> と表示される。 

# String.to_seq "abc";;
- : char Seq.t = <fun>
ミニ目標 1-3: List.of_seq によるリストへの変換

List.of_seq は、シーケンスを受け取り、 その要素を順番に格納したリストを返す関数である。 

(* List.of_seq : 'a Seq.t -> 'a list *)

型に現れる 'a は、要素の型を表す型変数である。 したがって、整数のシーケンスを渡せば int list が返り、文字のシーケンスを渡せば char list が返る。

今回は String.to_seq が返した char Seq.t を渡すので、 List.of_seq の型変数 'a は char になる。 

List.of_seq : char Seq.t -> char list

以上をまとめて、文字列をパーサの入力へ変換する chars_of_string を次のように定義する。 

(* stringで受け取ったソースコード列をinput型(charのリスト)に変換する *)
(* chars_of_string : string -> input *)
let chars_of_string s =
  List.of_seq (String.to_seq s)

input は char list の別名なので、 型を展開すると、chars_of_string の型は 次のものと同じである。 

(* chars_of_string : string -> char list *)

例えば、次の式を評価する。 

chars_of_string "12+3"

まず、内側の String.to_seq が 文字列を文字のシーケンスへ変換する。 次に、外側の List.of_seq が そのシーケンスを文字のリストへ変換する。 最終的な結果は次の通りである。 

['1'; '2'; '+'; '3']

以後のパーサは、この文字リストを入力として受け取る。 先頭の文字を消費するときは、 文字列の添字を操作する代わりに、 リストに対するパターンマッチを使う。

サブ目標 2: 1文字を処理する

「入力された文字列の先頭から、条件に合う1文字だけを読み取る」という処理は、以下の2つのミニ目標を組み合わせることで実現できる。
  • ミニ目標 2-1: 条件を満たす1文字だけを読む (satisfy)
    入力の先頭の1文字を調べ、与えられた条件関数 cond を満たす場合のみ、その文字と残りのリストを返す関数を作る。
  • ミニ目標 2-2: 特定の1文字を読む (char_p)
    ミニ目標 2-1 を利用し、「指定した文字 c と一致するか」という条件を与えることで、特定の1文字を読み取る関数を作る。 
(* 条件condを満たすなら、次の1文字を読み取る *)
(* satisfy : (char -> bool) -> input -> (char * input) option *)
let satisfy cond input =
  match input with
  | c :: cs when cond c -> Some (c, cs)
  | _ -> None

パターンの後ろに書かれている when は、 そのパターンに追加の条件を付けるための構文であり、 「ガード」と呼ばれる。 パターンに一致し、さらに when の後ろの条件式が true になった場合だけ、その処理が実行される。 

| c :: cs when cond c -> Some (c, cs)

この場合は、入力が空でないリスト c :: cs であり、さらに先頭文字 c が 条件 cond を満たす場合だけ、パースに成功する。 条件を満たさない場合は次のパターンへ進み、 None を返す。

satisfy は汎用的な関数である。引数として「文字を受け取って真偽値を返す関数（cond）」を受け取るため、後述の「数字かどうか」の判定など、様々な用途に使い回すことができる。 
(* 指定した文字cと一致するかどうかを判定する *)
(* char_p : char -> input -> (char * input) option *)
let char_p c input =
  satisfy (fun x -> x = c) input

satisfyに渡す関数は、与えられた条件をチェックするための関数である。今回の条件は、fun x -> x = c であり、これは文字 x が指定された文字 c と等しいかどうかを判定する。

サブ目標 3: 不要な文字を読み飛ばす

プログラムの意味に影響を与えない空白文字（スペースや改行など）を処理する。これはこれ以上分割せず、1つの関数として実装する。
  • ミニ目標 3-1: 空白文字の読み飛ばし (skip_spaces)
    入力の先頭が空白文字であれば、それを捨てて再帰的に次の文字を調べる。空白以外の文字が現れた時点で、その残りのリストをそのまま返す。 
(* スペースを飛ばす *)
(* skip_spaces : input -> input *)
let rec skip_spaces input =
  match input with
  (* ' 'はスペース, '\t'はタブ, '\n'は改行, '\r'はキャリッジリターン(Windows等の改行コードの一部)を表す *)
  | c :: cs when c = ' ' || c = '\t' || c = '\n' || c = '\r' ->
      skip_spaces cs (* 空白だったので、残りのリスト cs に対して再帰的に処理を続ける *)
  | _ -> input       (* 空白以外の文字が来たら、あるいはリストが空になったら、現在のリストをそのまま返す *)

サブ目標 4: 意味のある塊（トークン）を切り出す

最後に、「数字が連続していれば束ねて整数に変換し、特定の文字列が来れば記号またはキーワードとして切り出す」という処理を実装する。

ここで、記号とキーワードは区別して考える。 +、*、-> などは記号であり、 指定された文字列と入力の先頭が一致しているかを確認すればよい。 一方、if、then、true などはキーワードであり、 変数名として使用できる識別子と区別する必要がある。

例えば、入力が "if true then 1 else 2" であれば、 先頭の "if" はキーワードとして読み取る。 しかし、入力が "ifx" である場合は、 先頭の2文字が "if" と一致していても、 "ifx" 全体を一つの識別子として扱う必要がある。 したがって、キーワードの読み取りでは、 文字列が一致することに加えて、 その直後に識別子を構成する文字が続いていないことも確認する。

なお、現段階ではまだ if 式そのものを構文解析の対象にはしていない。ここで if を使用しているのは、キーワードを読み取る処理の例を示すためである。ここでは後の拡張でも再利用できる一般的な keyword_p を先に作成し、実際に if 式を構文解析する処理は後の節で追加する。

この処理は、以下の4つのミニ目標に分割する。

  • ミニ目標 4-1: 整数の切り出し（int_p）
    数字（'0'〜'9'）が連続している間だけ文字を読み進め、 それらを束ねてOCamlの int 型に変換して返す。
  • ミニ目標 4-2: 指定された文字列との一致確認（string_p）
    指定された文字列と入力の先頭が順番に一致するかを確認する。 この関数は、記号とキーワードの両方を読み取るための共通部品として使用する。
  • ミニ目標 4-3: 記号の切り出し（symbol_p）
    +、*、=、-> などの記号と 入力の先頭が一致するかを確認し、一致すればその記号と残りの入力を返す。
  • ミニ目標 4-4: キーワードの切り出し（keyword_p）
    if、then、true などのキーワードと 入力の先頭が一致するかを確認する。 さらに、キーワードの直後に英数字またはアンダースコアが続いていないことを確認し、 識別子の一部分をキーワードとして誤って切り出さないようにする。
ミニ目標 4-1: 整数の切り出し（int_p）
(* 数字の列が続く限り、束ねて整数に変換する *)
(* int_p : input -> (int * input) option *)
let int_p input =
  let is_digit c =
    c >= '0' && c <= '9' in
  
  (* 補助関数、数字が続く限り、acc（アキュムレータ）に文字を溜め込む *)
  (* read_digits : input -> char list -> char list * input *)
  let rec read_digits chars acc =
    match chars with
    | c :: cs when is_digit c -> read_digits cs (c :: acc)
    | _ -> (List.rev acc, chars)
  in
  
  match read_digits input [] with
  | ([], _) -> None
      (* アキュムレータが空、つまり最初から数字が一つもなかった場合 *)
      
  | (digits, rest) ->
      (* 文字のリストを文字列に変換してから、整数に変換する *)
      let str = String.of_seq (List.to_seq digits) in
      Some (int_of_string str, rest)
ここで登場した acc（アキュムレータ）とは、 再帰呼び出しの中で「計算の途中結果を蓄積しておくための引数」のことである。 たとえば入力が ['1'; '2'; '+'] だった場合、 read_digits は以下のように動作する。
  1. read_digits ['1'; '2'; '+'] [] が呼ばれる。
  2. '1' は数字なので、acc に追加して再帰する。 read_digits ['2'; '+'] ['1']
  3. '2' は数字なので、acc に追加して再帰する。 read_digits ['+'] ['2'; '1']
  4. '+' は数字ではないので終了する。 この時点で acc は ['2'; '1'] である。 List.rev acc によって順序を戻してから、 (['1'; '2'], ['+']) が返る。

文字を acc の先頭へ追加しているため、 読み取った途中の文字列は逆順になる。 終了時に List.rev を使って acc を ['1'; '2'] の順へ戻すことで、 正しい数字の並びを取得している。

ミニ目標 4-2: 指定された文字列との一致確認（string_p）

記号とキーワードは、どちらも複数の文字から構成される可能性がある。 例えば、+ は1文字の記号だが、 -> は2文字の記号であり、 then は4文字のキーワードである。

そこで、指定された文字列と入力の先頭が順番に一致するかを確認する 共通の関数 string_p を作る。 

(* 指定された文字列と入力の先頭が一致するか確認する *)
(* string_p : string -> input -> (string * input) option *)
let string_p expected input =
  
  (* targetの文字リストと、現在の入力charsが順番に一致するか確認する *)
  (* check_chars : input -> char list -> (string * input) option *)
  let rec check_chars chars target =
    match target with
    | [] ->
        Some (expected, chars)
        (* targetをすべて読み終えたので、文字列全体が一致した *)
        
    | t :: ts ->
        (match char_p t chars with
         | Some (_, rest) ->
             check_chars rest ts
             (* 1文字一致したので、残りの文字を確認する *)
             
         | None ->
             None)
             (* 途中で一致しない文字が見つかった *)
  in
  
  check_chars input (chars_of_string expected)

string_p は、第1引数として確認したい文字列 expected を受け取る。 その文字列を chars_of_string によって文字リストへ変換し、 入力の文字リストと先頭から一文字ずつ比較する。

例えば、次の呼び出しを考える。 

string_p "->" ['-'; '>'; ' '; 'x']

check_chars は、最初に '-'、 次に '>' が一致することを確認する。 確認対象をすべて読み終えた時点で、残っている入力は [' '; 'x'] であるため、結果は次のようになる。 

Some ("->", [' '; 'x'])

途中で一文字でも一致しなければ None を返す。

ミニ目標 4-3: 記号の切り出し（symbol_p）

+、*、=、-> などの記号は、 指定された文字列と入力の先頭が一致すれば読み取りに成功してよい。 そのため、記号の読み取りには、先ほど定義した string_p をそのまま利用できる。 

(* +、*、=、-> などの記号を読む *)
(* symbol_p : string -> input -> (string * input) option *)
let symbol_p symbol input =
  string_p symbol input

例えば、次の式は入力の先頭にある + を読み取る。 

symbol_p "+" ['+'; '1'; '2']

結果は次の通りである。 

Some ("+", ['1'; '2'])

symbol_p の内部処理は現時点では string_p を呼び出すだけである。 それでも別の関数として定義するのは、 「この文字列を記号として読んでいる」という目的を関数名から明確にするためである。

ミニ目標 4-4: キーワードの切り出し（keyword_p）

キーワードも、最初は string_p を使って 入力の先頭と一致するかを確認する。 ただし、キーワードでは、文字列が一致しただけで 直ちに成功としてはいけない。

例えば、keyword_p "if" を使って 次の入力を調べる場合を考える。 

['i'; 'f'; 'x']

先頭の2文字だけを見ると "if" と一致している。 しかし、この入力は if というキーワードの後ろに 変数 x が続いているのではなく、 ifx という一つの識別子であると考えるべきである。

そのため、キーワードの文字列が一致した後で、 残りの入力の先頭文字を確認する。 次の文字がアルファベット、数字、アンダースコアのいずれかであれば、 その文字は識別子の続きになり得る。 この場合は、読み取った文字列が識別子の一部分である可能性があるため、 キーワードとしての読み取りを失敗させる。 

(* 識別子の続きを構成できる文字かを判定する *)
(* is_ident_letter : char -> bool *)
let is_ident_letter c =
  (c >= 'a' && c <= 'z')
  || (c >= 'A' && c <= 'Z')
  || (c >= '0' && c <= '9')
  || c = '_'

is_ident_letter は、文字が識別子の途中に現れ得るかを判定する。 例えば、次の文字については true を返す。 

is_ident_letter 'a'
is_ident_letter 'Z'
is_ident_letter '3'
is_ident_letter '_'

一方、空白や演算子などに対しては false を返す。 

is_ident_letter ' '
is_ident_letter '+'
is_ident_letter '('

この判定関数を使って、キーワードを読み取る keyword_p を次のように定義する。 

(* if、then、true などの予約語を読む *)
(* 識別子の途中には一致させない *)
(* keyword_p : string -> input -> (string * input) option *)
let keyword_p keyword input =
  match string_p keyword input with
  | None ->
      None
      (* キーワードの文字列そのものが一致しなかった *)
      
  | Some (_, c :: _) when is_ident_letter c ->
      None
      (* 文字列は一致したが、その直後が識別子の続きなので、
         キーワードの一部分ではなく、一つの識別子とみなす *)
      
  | Some (_, rest) ->
      Some (keyword, rest)
      (* 文字列が一致し、その直後も識別子の続きではないので成功 *)

例えば、次の入力では "if" の直後に空白があるため、 キーワードとしての読み取りに成功する。 

keyword_p "if" ['i'; 'f'; ' '; 'x']

結果は次の通りである。 

Some ("if", [' '; 'x'])

一方、次の入力では "if" の直後に 識別子を構成できる文字 'x' が続いている。 

keyword_p "if" ['i'; 'f'; 'x']

この場合、入力は ifx という一つの識別子であるため、 keyword_p "if" は None を返す。 

None

同様に、keyword_p "true" は true には成功するが、 truevalue の先頭だけを true として 読み取ることはない。

このように、string_p は単純な文字列の一致確認、 symbol_p は記号の読み取り、 keyword_p は識別子との境界を確認したキーワードの読み取り、 という異なる役割を持つ。

ここまでに定義した関数群だけで、eval1 で扱う構文（整数、+、*）を文字リストからトークンとして切り出すための部品はすべて揃っている。この後作成する構文解析器（parser）は、これらの関数を呼び出して結果を繋ぎ合わせるだけで構成できる。

課題 4-2-1 (字句解析器の確認)

ここまでに作成した字句解析の部品を、通常のソースコードと同じ string 型の入力からまとめて確認する。そのために、整数と記号を同じ型で表す、確認用の lexeme 型を定義する。

type lexeme =
  | IntLexeme of int
  | SymbolLexeme of string

(* lex_one_chars : input -> (lexeme * input) option *)
let lex_one_chars input =
  let input = skip_spaces input in
  match int_p input with
  | Some (n, rest) -> Some (IntLexeme n, rest)
  | None ->
      (match symbol_p "+" input with
       | Some (s, rest) -> Some (SymbolLexeme s, rest)
       | None ->
           match symbol_p "*" input with
           | Some (s, rest) -> Some (SymbolLexeme s, rest)
           | None -> None)

(* lex_one : string -> (lexeme * input) option *)
let lex_one source =
  lex_one_chars (chars_of_string source)

lex_one は、chars_of_string で文字列を文字リストへ変換し、skip_spaces で先頭の空白を読み飛ばした後、int_p または symbol_p を使って字句を一つ読み取る。この関数によって、サブ目標1から4までの処理が一連の流れとして接続されていることを確認できる。

テスト・データ:

(* 期待される出力: Some (IntLexeme 42, [' '; '*'; ' '; '2']) *)
let test2 = lex_one "   42 * 2" ;;

(* 期待される出力: Some (SymbolLexeme "+", [' '; '3']) *)
let test3 = lex_one "+ 3" ;;

(* 期待される出力: Some (SymbolLexeme "*", ['1'; '0']) *)
let test4 = lex_one "*10" ;;

(* 期待される出力: None *)
let test5 = lex_one "@ 3" ;;

さらに、lex_one_chars を拡張し、引き算（-）と割り算（/）も SymbolLexeme として読み取れるようにしなさい。

なお、以後の構文解析器では、確認用の lexeme の列を先に作るのではなく、int_p、symbol_p、keyword_p を必要な位置で直接呼び出す。lex_one は、ここまでの字句解析の部品を統合して確認するためのエントリーポイントである。

構文解析器 (parser) の実装方針

構文解析器は、字句解析の機能を利用してトークンの列を読み込み、文法の定義に応じた木（構文木、すなわち exp 型のデータ）を組み立てる。これも字句解析と同様に、以下のように要素ごとに処理を分割できる。

（※前述の通り、現段階では 整数、足し算、かけ算のみを対象とし、if 式や真偽値などの複合的な構文は後から追加していく。）

  • 式の基本要素を組み立てる: 整数など、それ以上分割できない最小単位の式を読み取って構文木（IntLit）にする機能を作る。
  • 演算式を組み立てる: + や * などの演算子を読み取り、その左辺の構文木と右辺の構文木を繋ぎ合わせて、1つの大きな構文木（Plus や Times）にする機能を作る。
このように、「文字列を受け取り、目的のデータ（トークンや構文木）を読み取り、残りの文字列をペアにして返す」という共通の構造を持つ小さな関数（部品）をたくさん作り、それらを繋ぎ合わせていくことで、最終的に巨大な1つの構文解析器を構築することができる。

それでは、最も基本的な部品の作成から順番に見ていこう。

2. 構文解析器（parser）の実装

字句解析の部品（int_p や keyword_p など）が揃ったので、これらを利用して構文解析器を作っていく。 ここでの目標は、入力された文字のリストから意味のあるトークンを読み取り、最終的に exp 型の「抽象構文木（AST）」を構築することである。

処理の優先順位（かけ算は足し算より先に計算するなど）を正しく反映させるため、構文解析もいくつかの「ミニ目標」に分割して順番に呼び出していく。

サブ目標 5: 式の基本要素を組み立てる

まずは、これ以上分割できない最小単位の式、今回の範囲では「整数」のみを、構文木に変換する関数を作る。

  • ミニ目標 5-1: 最小単位（整数リテラル）のパース (primary_expr)
    字句解析で作った int_p を呼び出して整数を読み取り、得られた整数 n を IntLit(n) という構文木で包んで返す。

  let input_after_spaces = skip_spaces input in

  match int_p input_after_spaces with
  | Some (n, rest) -> 
      (* 整数 n が読めたら、それを IntLit(n) という AST に変換して返す *)
      Some (IntLit n, rest)
  | None -> None
この関数により、たとえば [' '; '4'; '2'] という入力を与えると、Some (IntLit 42, []) が返ってくるようになる。これが構文木の「葉（一番端の部分）」となる。

サブ目標 7: 括弧で囲まれた算術式の追加

これまでの実装では、かけ算を足し算よりも先に結合するという通常の優先順位に従って構文木を作っていた。しかし、(1 + 2) * 3 のように、括弧によって通常とは異なる順番で式を結合したい場合もある。

括弧は新しい計算を表すものではないため、括弧そのものに対応する構文木は作らない。開き括弧を読み、内部の式を解析し、閉じ括弧を確認した後、内部で作られた構文木をそのまま返す。

現段階で扱える式全体は足し算式までなので、括弧の内部は plus_expr を使って解析する。後の節で if 式や let 式などを追加した後には、括弧の内部を、すべての式を扱う入口である expr で解析するように一般化する。

  • ミニ目標 7-1: 開き括弧、内部の算術式、閉じ括弧の読み取り
    ( を読み、その内部を plus_expr で解析した後、) を読む。括弧そのものに対応するASTは作らず、内部の式をそのまま返す。
  • ミニ目標 7-2: primary_expr への括弧の追加
    整数の読み取りに失敗した場合には paren_expr を試し、括弧で囲まれた式も基本要素として扱えるようにする。

primary_expr は paren_expr を呼び、paren_expr は plus_expr を呼ぶ。また、plus_expr は times_expr を通じて再び primary_expr を呼ぶ。そのため、この4つの関数は let rec ... and ... による相互再帰として定義する。

  match int_p input_after_spaces with
  | Some (n, rest) ->
      Some (IntLit n, rest)
  | None ->
      paren_expr input_after_spaces

サブ目標 10: 字句解析器（lexer）の確認

新しい構文を読み取るにあたり、字句解析器に新しい関数を追加する必要があるだろうか？ 実は、追加する必要はない。 すでに作成した keyword_p は、「指定した文字列と一致するか」を判定する汎用的な関数である。したがって、keyword_p "true" や symbol_p "=" と呼び出すだけで、真偽値や比較演算子も独立したトークンとして簡単に切り出すことができる。これが、問題を小さな関数に分割して組み立てる手法（モジュール化という）の大きな利点である。

サブ目標 11: 構文解析器の基本要素（葉）の拡張

字句解析の準備ができているので、さっそく構文解析器を拡張する。まずは一番優先度が高く、ASTの末端（葉）となる primary_expr に真偽値を追加する。
  • ミニ目標 11-1: true と false のパース
    入力文字列が整数でなかった場合、次に "true" であるか試し、それも失敗したら "false" であるか試すように match 式をネスト（入れ子）にして処理を繋ぐ。 
(* ミニ目標 11-1: 最小単位（整数と真偽値）のパース *)
(* primary_expr : input -> (exp * input) option *)
let rec primary_expr input =
  let input = skip_spaces input in
  
  (* 1. まず整数か試す *)
  match int_p input with
  | Some (n, rest) -> Some (IntLit n, rest)
  | None ->
      
      (* 2. 整数でなければ "true" か試す *)
      (match keyword_p "true" input with
       | Some (_, rest) -> Some (BoolLit true, rest)
       | None ->
           
           (* 3. "true" でもなければ "false" か試す *)
           (match keyword_p "false" input with
            | Some (_, rest) -> Some (BoolLit false, rest)
            | None -> None)) (* 全てに失敗したら None を返す *)

サブ目標 12: 比較演算式のパース（新しい優先順位の追加）

次に、比較演算子 = のパース処理を追加する。 ここで文法の「優先順位」について考えてみよう。 1 + 2 = 3 という式は、 (1 + 2) = 3 と解釈されるべきであり、 1 + (2 = 3) と解釈されてはならない。 つまり、「比較演算子は、足し算よりも優先順位が低い」 ということになる。

これを実装に落とし込むには、 これまでエントリーポイントだった plus_expr をさらに外側から呼び出す新しい関数 comp_expr を作ればよい。

また、 = < > などの比較演算子は左結合として定義されている。 そこで、1 = 2 = 3 のように比較演算子が連続した場合にも対応できるよう、 足し算やかけ算と同様にアキュムレータを使って構文木を組み立てる。 

1 = 2 = 3

      ↓ 左結合

Eq (Eq (IntLit 1, IntLit 2), IntLit 3)

ただし、このような構文木を作れることと、 その式が正しい型を持つことは別の問題である。 1 = 2 の結果は真偽値なので、 その結果と整数 3 を比較する式は、 後の型検査または評価の段階でエラーになる。 構文解析器の役割は、ここでは入力の構造に従って 構文木を作るところまでである。

  • ミニ目標 12-1: 左辺（足し算式）の読み取り
    比較演算の構成要素は、より優先度の高い plus_expr であるため、 まずはこれを呼び出して左辺 e1 を取得する。
  • ミニ目標 12-2: 連続する比較演算のためのアキュムレータの準備
    最初に読み取った左辺をアキュムレータ current_e として保持し、 比較演算子が続く限り構文木を更新する 補助関数 parse_rest を用意する。
  • ミニ目標 12-3: = と右辺の読み取り
    入力の先頭に = があれば、 その右辺を plus_expr で読み取る。
  • ミニ目標 12-4: 構文木の結合と再帰
    現在の構文木 current_e と 新しく読み取った右辺 e2 から Eq (current_e, e2) を作り、 それを新しいアキュムレータとして処理を続ける。
  • ミニ目標 12-5: 比較演算子がない場合の処理
    = が続かなければ、 現在までに作った構文木をそのまま返す。 
(* ミニ目標 11: 比較演算のパース *)
(* comp_expr : input -> (exp * input) option *)
let rec comp_expr input =
  
  (* ミニ目標 12-1:
     最初の左辺を plus_expr で読み取る *)
  match plus_expr input with
  | None ->None
  | Some (e1, rest1) ->
      
      (* ミニ目標 12-2:current_e に、ここまでに作った構文木を保持する *)
      (* parse_rest : exp -> input -> (exp * input) option *)
      let rec parse_rest current_e current_rest =
        let r = skip_spaces current_rest in
        
        (* ミニ目標 12-3:比較演算子 "=" が続くか確認する *)
        match symbol_p "=" r with
        | None -> Some (current_e, current_rest) (* ミニ目標 12-5:比較演算子がなければ現在の木を返す *)
        | Some (_, rest2) ->
            (* "=" の右辺を読み取る *)
            (match plus_expr rest2 with
             | None -> None (* "=" があるのに右辺がないため、比較式として失敗する *)
             | Some (e2, rest3) ->
                 (* ミニ目標 12-4:左右の式から新しい Eq を作り、さらに比較演算子が続くか調べる *)
                 let new_e = Eq (current_e, e2) in
                 parse_rest new_e rest3)
      in
      parse_rest e1 rest1

サブ目標 13: エントリーポイントの更新

最後に、文字列を受け取ってパースを開始する parse 関数を更新する。一番優先順位の低い関数が plus_expr から comp_expr に変わったため、呼び出し元を変更するだけでよい。
  • ミニ目標 13-1: parse 関数の呼び出し先変更
    match plus_expr chars with となっていた部分を match comp_expr chars with に書き換える。 
(* ミニ目標 13-1: エントリーポイントの更新 *)
(* parse : string -> exp *)
let parse s =
  let chars = chars_of_string s in
  
  (* 一番優先順位の低い comp_expr からパースを開始する *)
  match comp_expr chars with
  | Some (ast, rest) -> 
      let final_rest = skip_spaces rest in
      if final_rest = [] then ast
      else failwith "Parse Error: 式の後ろに余分な文字があります"
  | None -> failwith "Parse Error"
これで、真偽値と等価演算子（=）が正しくパースできるようになった。

  • ミニ目標 15-2: then と真の場合の式 (e2) の読み取り
    条件式 e1 の後ろの空白を読み飛ばし、"then" が続くか確認する。一致すれば、それに続く式（e2）をパースする。
  • ミニ目標 15-3: else と偽の場合の式 (e3) の読み取りおよびAST構築

  • ミニ目標 15-4: if で始まらない場合の処理
    もし最初の段階で "if" が見つからなければ、この文字列は if 式ではない（単なる比較式や足し算などである）とみなし、比較式のパース処理（comp_expr）にそのまま処理を委譲する。 
(* サブ目標 15: if式のパース *)
(* if_expr : input -> (exp * input) option *)
let rec if_expr input =
  let r1 = skip_spaces input in
  
  (* ミニ目標 15-1: "if" と条件式(e1)の読み取り *)
  match keyword_p "if" r1 with
  | Some (_, rest1) ->
      (match if_expr rest1 with
       | Some (e1, rest2) ->
           
           (* ミニ目標 15-2: "then" と真の場合の式(e2)の読み取り *)
           let r2 = skip_spaces rest2 in
           (match keyword_p "then" r2 with
            | Some (_, rest3) ->
                (match if_expr rest3 with
                 | Some (e2, rest4) ->
                     
                     (* ミニ目標 15-3: "else" と偽の場合の式(e3)の読み取りおよびAST構築 *)
                     let r3 = skip_spaces rest4 in
                     (match keyword_p "else" r3 with
                      | Some (_, rest5) ->
                          (match if_expr rest5 with
                           | Some (e3, rest6) -> 
                               (* 全て揃ったので If の構文木を作って返す *)
                               Some (If (e1, e2, e3), rest6)
                           | None -> None)
                      | None -> None)
                 | None -> None)
            | None -> None)
       | None -> None)
       
  | None ->
      (* ミニ目標 15-4: "if" で始まらない場合は comp_expr に任せる *)
      comp_expr input

5. 高階関数の導入とパーサコンビネータによる構文解析

前節で if 式のパースを実装したが、match 式の中に match 式が入る「入れ子」が深くなり、冗長なコードとなってしまった。

この実験は美しく、簡潔にプログラミングしよう！という趣旨であるので、このような冗長な書き方は許しがたい。というわけで、見た目の美しさと保守性を追求して、共通する処理を1つにまとめることにする。

全体の見通しを良くするため、まずは本節で順番に取り組むサブ目標を列挙しておこう。

  • サブ目標 17: bind と return の定義
    「パースが成功したら、その結果を使って次のパースを行う」という共通処理を、1つの高階関数としてくくり出す。
  • サブ目標 18: bind による if_expr の書き換え
    定義した bind 関数を使うと、冗長だった match と None の処理を省略できることを確認する。
  • サブ目標 19: 束縛演算子 let* の導入
    同じ bind の連鎖を上から下へ読める形にする。

サブ目標 17: bind と return の定義

(* bind : (input -> ('a * input) option) ->
          ('a -> input -> ('b * input) option) ->
          input -> ('b * input) option *)
let bind p f =
  fun input ->
    match p input with
    | None -> None
    | Some (v, rest) -> f v rest

(* return : 'a -> input -> ('a * input) option *)
let return v =
  fun input -> Some (v, input)

(* token : (input -> ('a * input) option) ->
           input -> ('a * input) option *)
let token p =
  bind p (fun v ->
    fun input -> Some (v, skip_spaces input))

ここでわかるように、bind の第2引数 f は、関数である。p が成功した場合だけ、読み取った値 v を f に渡して次のパースへ進む。一方、p が失敗した場合は、後続の処理を実行せずに None を返す。

サブ目標 18: bind による if_expr の書き換え

(* if_expr : input -> (exp * input) option *)
let rec if_expr input =
  bind (token (keyword_p "if")) (fun _ ->
    bind if_expr (fun e1 ->
      bind (token (keyword_p "then")) (fun _ ->
        bind if_expr (fun e2 ->
          bind (token (keyword_p "else")) (fun _ ->
            bind if_expr (fun e3 ->
              return (If (e1, e2, e3))
            )
          )
        )
      )
    )
  ) input

このように、パース失敗時に None を返す処理と、残りの入力を次のパーサへ渡す処理は、bind の中に隠蔽された。そのため、以前の実装にあった match ... with の繰り返しはなくなっている。

しかし、match と None の反復は消えたが、今度は bind と fun ... -> の入れ子が深くなった。処理は順番にパーサを実行しているだけなのに、閉じ括弧が右側へ重なり、流れを追いにくい。

サブ目標 19: 束縛演算子 let* の導入

(* let* : (input -> ('a * input) option) ->
           ('a -> input -> ('b * input) option) ->
           input -> ('b * input) option *)
let ( let* ) p f =
    fun input ->
    match p input with
    | None -> None
    | Some (v, rest) -> f v rest

(* token : (input -> ('a * input) option) ->
           input -> ('a * input) option *)
let token p =
  let* v = p in
  fun input -> Some (v, skip_spaces input)

(* if_expr : input -> (exp * input) option *)
let rec if_expr input =
  (let* _  = token (keyword_p "if") in
   let* e1 = if_expr in
   let* _  = token (keyword_p "then") in
   let* e2 = if_expr in
   let* _  = token (keyword_p "else") in
   let* e3 = if_expr in
   return (If (e1, e2, e3)))
  input

let* x = p in e は、ここでは bind p (fun x -> e) と同じ意味になる。以後はこの形式を標準とする。

let* による括弧パーサの書き換え

サブ目標7では、括弧の処理を match 式の入れ子として実装した。ここまでで bind と let* を導入したため、同じ処理を、パーサを上から順番に実行する形へ書き直すことができる。

(* paren_expr : input -> (exp * input) option *)
let rec paren_expr input =
  (let* _ = token (symbol_p "(") in
   let* e = plus_expr in
   let* _ = token (symbol_p ")") in
   return e)
  input

このコードは、開き括弧、内部の式、閉じ括弧を順番に読むという処理を、その実行順序のまま記述している。いずれかのパーサが失敗した場合は、bind が後続の処理を実行せずに None を返すため、個々の段階で match ... with | None -> None を書く必要がない。

なお、この時点では括弧の内部を plus_expr で読んでいる。後に let 式、if 式、無名関数などをまとめたトップレベルの expr を定義した後、括弧内の呼び出し先を plus_expr から expr へ変更する。

独自の中置演算子による書き方（補足）

let ( >>= ) = bind

p >>= f と書く方法もあるが、本章では通常の変数束縛に近い let* を使用する。

6. 他の構文のコンビネータ化と次章への準備

if 式以外の構文解析処理（整数、足し算、比較）も、この let* を使ったパーサコンビネータのスタイルで書き直してみよう。

ここでは新しく、「左側のパーサを試し、失敗したら右側のパーサを試す」というバックトラック処理を隠蔽するコンビネータ <|> (alt) を導入する。これを使うと match ... with | None -> ... という分岐を消すことができる。

(* 選択実行の関数 (alt) *)
(* <|> :  ('a -> 'b option)
       -> ('a -> 'b option)
       -> 'a
       -> 'b option
*)
let ( <|> ) p1 p2 =
  fun input ->
    match p1 input with
    | Some _ as res -> res
    | None -> p2 input

例として、一番単純な整数（primary_expr）、足し算（plus_expr）、および等価演算子（comp_expr）を let* と <|> を使って書き直したコードを以下に示す。以前の match だらけのコードと見比べると、その読みやすさは歴然である。

（※ let* の範囲を明確にするため、<|> と組み合わせる際は (let* ... in ...) <|> return ... のように括弧でくくる点に注意すること。）

(* 例1: 最小単位（整数のみ）のパース *)
let rec primary_expr input =
  (let* n = token int_p in
   return (IntLit n))
  input

(* 例2: 足し算のパース *)
let rec plus_expr input =
  (* 左辺をパース *)
  (let* e1 = times_expr in
   
   (* アキュムレータを用いた再帰関数も、let* と <|> で書ける *)
   let rec parse_rest current_e =
     (let* _  = token (symbol_p "+") in
      let* e2 = times_expr in
      let new_e = Plus (current_e, e2) in
      parse_rest new_e)
     <|> return current_e  (* "+" が無ければ(失敗したら) current_e を返す *)
   in
   parse_rest e1)
  input

(* 例3: 比較演算(=)のパース *)
let rec comp_expr input =
  (let* e1 = plus_expr in
   
   (let* _  = token (symbol_p "=") in
    let* e2 = plus_expr in
    return (Eq (e1, e2)))
   <|> return e1) (* "=" が無ければ左辺 e1 をそのまま返す *)
  input

  2. 四則演算の完成: plus_expr と times_expr に、それぞれ引き算（-）と割り算（/）の処理を追加しなさい（+ のパースに失敗したら - を試すようにする）。

(* ミニ目標 20-1: ASTの拡張 *)
type exp =

サブ目標 21: 字句解析器の拡張（識別子と予約語の分離）

変数名（識別子）のパース処理を作成する。ここでは、変数名の最初の1文字はアルファベット、2文字目以降はアルファベット、数字、アンダースコア（_）の連続であるとする。
  • ミニ目標 21-1: 文字種の判定関数の用意
    文字がアルファベットであるか、あるいは英数字・アンダースコアであるかを判定する関数を用意する。
  • ミニ目標 21-2: 識別子の切り出しと予約語チェック (ident_p)
    先頭がアルファベットであれば文字の読み取りを開始し、続く英数字を束ねて文字列にする。その後、得られた文字列が予約語リストに含まれていないかチェックし、含まれていればパース失敗（None）とする。 
(* ミニ目標 21-1: 文字種の判定関数 *)
let is_alpha c = (c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z')
let is_alnum c = is_alpha c || (c >= '0' && c <= '9') || c = '_'

(* ミニ目標 21-2: 識別子（変数名）のパースと予約語チェック *)
(* 入力: 文字リスト (input) *)
(* 出力: 予約語以外の識別子が読めれば Some(変数名の文字列, 残りの文字リスト)、失敗すれば None *)
(* ident_p : input -> (string * input) option *)
let ident_p input =
  (* 英数字が続く限りアキュムレータ(acc)に溜め込む補助関数 *)
  let rec read_alnum chars acc =
    match chars with
    | c :: cs when is_alnum c -> read_alnum cs (c :: acc)
    | _ -> (List.rev acc, chars)
  in
  
  match input with
  | c :: cs when is_alpha c -> 
      (* 1文字目がアルファベットだった場合のみ、残りの英数字を読み取る *)
      let (alnums, rest) = read_alnum cs [c] in
      let str = String.of_seq (List.to_seq alnums) in
      
      (* 予約語（キーワード）のリスト *)
      let reserved = ["let"; "rec"; "in"; "if"; "then"; "else"; "fun"; "true"; "false"; "match"; "with"] in
      
      if List.mem str reserved then
        None (* 読み取った文字列が予約語だった場合は、変数名としてはパース失敗とする *)
      else
        Some (str, rest) (* 予約語でなければ、変数名として返す *)
        
  | _ -> None
予約語を除外しないと、if true then 1 else 2 の if を変数として誤認し、正しくパースできなくなる。これは言語処理系において一般的な手順である。

サブ目標 22: 構文解析器の基本要素（葉）の拡張

字句解析の ident_p を利用し、ASTの末端となる primary_expr を拡張して変数をパースできるようにする。前節の方針通り、let* 構文と選択実行のコンビネータ <|> を組み合わせて記述する。
  • ミニ目標 22-1: 変数のパース処理の追加
    primary_expr の選択肢の末尾に、ident_p を用いたパース処理を追加する。 
(* ミニ目標 22-1: 変数(Var)の追加 *)
let rec primary_expr input =
  ( (let* n = token int_p in return (IntLit n))
    <|> 
    (let* _ = token (keyword_p "true") in return (BoolLit true))
    <|> 
    (let* _ = token (keyword_p "false") in return (BoolLit false))
    <|> 
    (* 追加: 識別子が読めたら Var の構文木にする *)
    (let* x = token ident_p in return (Var x)) )
  input

サブ目標 23: let 式のパースとエントリーポイントの統合

次に let x = e1 in e2 をパースする処理を作成する。 let 式も if 式と同様に優先順位が低い構文である。そこで、構文解析のトップレベルの関数を expr という名前に統一し、let と if の両方を組み込む。
  • ミニ目標 23-1: let_expr の実装
    let* を使い、let、変数名（x）、=、式（e1）、in、式（e2）を順に読み取る。
  • ミニ目標 23-2: トップレベルの統合と parse の更新
    トップレベルのパーサ expr を新設し、let 式、if 式、比較式（comp_expr）の順にパースを試すようにする。 
(* 相互再帰的に呼び出すため、トップレベルを let rec expr ... and ... で繋ぐ *)

(* ミニ目標 23-2: トップレベルの統合パーサ *)
let rec expr input =
  (let_expr <|> if_expr <|> comp_expr) input

(* ミニ目標 23-1: let 式のパース *)
and let_expr input =
  (let* _  = token (keyword_p "let") in
   let* x  = token ident_p in          (* 変数名 x を読む *)
   let* _  = token (symbol_p "=") in
   let* e1 = expr in                   (* 束縛される式 e1 を読む *)
   let* _  = token (keyword_p "in") in
   let* e2 = expr in                   (* 続く本体の式 e2 を読む *)
   return (Let (x, e1, e2)))
  input

(* 以前作成した if_expr も、再帰呼び出し先を expr に変更する *)
and if_expr input =
  (let* _  = token (keyword_p "if") in
   let* e1 = expr in
   let* _  = token (keyword_p "then") in
   let* e2 = expr in
   let* _  = token (keyword_p "else") in
   let* e3 = expr in
   return (If (e1, e2, e3)))
  input

(* エントリーポイントの更新 *)
(* parse : string -> exp *)
let parse s =
  let chars = chars_of_string s in
  (* 全ての式の頂点である expr からパースを開始する *)
  match expr chars with
  | Some (ast, rest) -> 
      let final_rest = skip_spaces rest in
      if final_rest = [] then ast
      else failwith "Parse Error: 式の後ろに余分な文字があります"
  | None -> failwith "Parse Error"
（※ let_expr や if_expr の中で呼び出している再帰関数が comp_expr から expr に変わっている点に注意。これにより、let x = 1 in let y = 2 in x + y のように let 式の中にさらに let 式をネストさせることが可能になる。）

サブ目標 24: 関数を表す内部データ構造の確認

最初に、関数に関係する式と値の違いを確認する。構文解析器が生成する抽象構文木は exp 型である。そのため、関数の構文を解析するには、exp 型に次の構成子が必要である。

type exp =
  ...
  | Fun of string * exp
  | App of exp * exp
  | LetRec of string * string * exp * exp
  • Fun (x, body) は、仮引数 x と本体 body を持つ無名関数 fun x -> body を表す。
  • App (e1, e2) は、式 e1 を式 e2 に適用する関数適用 e1 e2 を表す。
  • LetRec (f, x, e1, e2) は、再帰関数定義 let rec f x = e1 in e2 を表す。

一方、value 型は式を評価して得られる値を表す。非再帰関数を評価した結果は、仮引数、本体、関数が作られた時点の環境をまとめたクロージャになる。そのため、value 型に FunVal を追加する。

type value =
  | IntVal of int
  | BoolVal of bool
  | FunVal of string * exp * ((string * value) list)

FunVal (x, body, env) は、仮引数 x、関数本体 body、関数を作った時点の環境 env を保存した関数クロージャである。

例えば、次の式を構文解析した結果は exp 型の値である。

fun x -> x + 1

↓ 構文解析

Fun ("x", Plus (Var "x", IntLit 1))

この Fun を評価すると、評価器は現在の環境を保存して、次のような value 型の値を返す。

FunVal ("x", Plus (Var "x", IntLit 1), env)

再帰関数については、値の型に RecFunVal を追加する。

type value =
  | IntVal of int
  | BoolVal of bool
  | FunVal of string * exp * ((string * value) list)
  | RecFunVal of
      string * string * exp * ((string * value) list)

RecFunVal (f, x, body, env) は、関数名 f、仮引数 x、関数本体 body、関数を定義した時点の環境 env を保存した再帰関数値である。

本節で作成する構文解析器は、FunVal や RecFunVal を直接生成しない。構文解析器は Fun、App、LetRec を含む exp 型の構文木を生成する。その構文木を後で評価器に渡すと、評価器が FunVal または RecFunVal を生成する。

サブ目標 25: 括弧で囲まれた式の一般化

サブ目標7では、括弧の内部を、その時点で最も一般的な式だった plus_expr で解析した。しかし、現在は if 式、let 式、無名関数なども扱うため、括弧の内部には任意の式が現れ得る。

そこで、括弧内の呼び出し先を plus_expr から、すべての式を扱う入口である expr へ変更する。括弧は構文木に新しい節点を作るものではなく、内部の式をそのまま返し、式の結合の仕方だけを変更する。

  • ミニ目標 25-1: 開き括弧 ( を読む。
  • ミニ目標 25-2: 括弧の内部を expr で読む。
  • ミニ目標 25-3: 閉じ括弧 ) を読み、内部の式を返す。
(* paren_expr : input -> (exp * input) option *)
and paren_expr input =
  (let* _ = token (symbol_p "(") in
   let* e = expr in
   let* _ = token (symbol_p ")") in
   return e)
  input

let* e = expr が重要である。ここを plus_expr にすると、括弧内にある if 式、let 式、無名関数などを解析できない。

paren_expr は expr を呼び、expr は最終的に primary_expr を通じて paren_expr を呼ぶ。そのため、実際に統合するときは、これらを let rec ... and ... による相互再帰として定義する。

サブ目標 26: 関数適用

関数適用 f x には、+ や * のような区切り記号がない。そこで、「基本式を一つ読んだ後、さらに基本式が続く間は引数として読む」という方針をとる。

  • ミニ目標 26-1: 関数の位置にある最初の primary_expr を読む。
  • ミニ目標 26-2: 次の primary_expr が読めたら App を作る。
  • ミニ目標 26-3: 引数が続く限り、作った App をアキュムレータとして繰り返す。
  • ミニ目標 26-4: 次の基本式がなければ、現在の構文木を返す。
(* app_expr : input -> (exp * input) option *)
and app_expr input =
  (let* first = primary_expr in

   (* parse_rest : exp -> input -> (exp * input) option *)
   let rec parse_rest current =
     (let* argument = primary_expr in
      parse_rest (App (current, argument)))
     <|>
     return current
   in

   parse_rest first)
  input

例えば f x y では、アキュムレータ current が次のように変化する。

Var "f"

App (Var "f", Var "x")

App (App (Var "f", Var "x"), Var "y")

最終的に生成される構文木は次のとおりである。

App (App (Var "f", Var "x"), Var "y")

これは (f x) y を表すため、関数適用は左結合になる。右結合にすると f (x y) という別の式になってしまう。

関数適用は乗算や加算より強く結合する。したがって、従来の times_div_expr が primary_expr を呼んでいた箇所を、app_expr の呼び出しに変更する。

primary_expr
    ↓
app_expr
    ↓
times_div_expr
    ↓
plus_minus_expr
    ↓
comp_expr
    ↓
expr

times_div_expr は次のように変更する。

(* times_div_expr : input -> (exp * input) option *)
and times_div_expr input =
  (let* e1 = app_expr in

   let rec parse_rest current_e =
     ((let* _ = token (symbol_p "*") in
       let* e2 = app_expr in
       parse_rest (Times (current_e, e2)))
      <|>
      (let* _ = token (symbol_p "/") in
       let* e2 = app_expr in
       parse_rest (Div (current_e, e2)))
      <|>
      return current_e)
   in

   parse_rest e1)
  input

これにより、f x * 2 は次の構文木になる。

Times (
  App (Var "f", Var "x"),
  IntLit 2
)

サブ目標 27: 無名関数

無名関数は、fun、仮引数、->、関数本体の4つを順番に読む。

(* fun_expr : input -> (exp * input) option *)
and fun_expr input =
  (let* _ = token (keyword_p "fun") in
   let* x = token ident_p in
   let* _ = token (symbol_p "->") in
   let* body = expr in
   return (Fun (x, body)))
  input

body は expr で読む。例えば、次の式を考える。

fun x -> x + 1

関数本体は x だけではなく、x + 1 全体である。そのため、primary_expr ではなく expr を使用する。

同様に、次のように関数本体へ if 式や let 式を置くこともできる。

fun x -> if x = 0 then 1 else x

fun x -> let y = x + 1 in y * 2

-> は識別子ではなく記号なので、keyword_p ではなく symbol_p で読む。

サブ目標 28: 名前付き関数定義

let f x = e1 in e2 は、既存の let 式と無名関数を使った次の式へ変換できる。

let f x = e1 in e2

     ↓ 脱糖

let f = fun x -> e1 in e2

名前付き関数定義のために新しい exp 型の構成子を追加する必要はない。構文解析の時点で、既存の Let と Fun を組み合わせた構文木へ変換する。

(* named_fun_expr : input -> (exp * input) option *)
and named_fun_expr input =
  (let* _ = token (keyword_p "let") in
   let* f = token ident_p in
   let* x = token ident_p in
   let* _ = token (symbol_p "=") in
   let* e1 = expr in
   let* _ = token (keyword_p "in") in
   let* e2 = expr in
   return (Let (f, Fun (x, e1), e2)))
  input

例えば、次の入力を考える。

let add x = x + 1 in add 3

構文解析器は、これを次の構文木へ変換する。

Let (
  "add",
  Fun ("x", Plus (Var "x", IntLit 1)),
  App (Var "add", IntLit 3)
)

複数引数の名前付き関数定義も、無名関数を入れ子にすることで表現できる。

let add x y = x + y in add 1 2

     ↓ 脱糖

let add =
  fun x ->
    fun y ->
      x + y
in
  add 1 2

対応する構文木は次のようになる。

Let (
  "add",
  Fun (
    "x",
    Fun (
      "y",
      Plus (Var "x", Var "y")
    )
  ),
  App (
    App (Var "add", IntLit 1),
    IntLit 2
  )
)

複数引数版は課題とする。

サブ目標 29: 再帰関数

通常の let 式では、定義される関数自身をその関数本体から参照できない。そこで、let rec 式は専用の LetRec 構文として解析する。

(* let_rec_expr : input -> (exp * input) option *)
and let_rec_expr input =
  (let* _ = token (keyword_p "let") in
   let* _ = token (keyword_p "rec") in
   let* f = token ident_p in
   let* x = token ident_p in
   let* _ = token (symbol_p "=") in
   let* e1 = expr in
   let* _ = token (keyword_p "in") in
   let* e2 = expr in
   return (LetRec (f, x, e1, e2)))
  input

例えば、次の再帰関数定義を考える。

let rec factorial x =
  if x = 0 then
    1
  else
    x * factorial (x - 1)
in
  factorial 5

構文解析器は、この式から概略として次の構文木を作る。

LetRec (
  "factorial",
  "x",
  If (
    Eq (Var "x", IntLit 0),
    IntLit 1,
    Times (
      Var "x",
      App (
        Var "factorial",
        Minus (Var "x", IntLit 1)
      )
    )
  ),
  App (Var "factorial", IntLit 5)
)

この時点で生成されるのは LetRec を含む exp 型の値であり、RecFunVal ではない。

後で評価器が LetRec (f, x, e1, e2) を評価するとき、次の形の再帰関数値を作る。

RecFunVal (f, x, e1, env)

したがって、構文解析と評価の対応は次のとおりである。

入力文字列
  "let rec f x = e1 in e2"
        ↓ 構文解析
exp型
  LetRec (f, x, e1, e2)
        ↓ 評価
value型
  RecFunVal (f, x, e1, env)

let rec、名前付き関数定義、通常の let 式は、いずれも let から始まる。選択肢を並べるときは、より具体的な構文から順番に試す。

  1. let_rec_expr が let rec f x = ... を試す。
  2. named_fun_expr が let f x = ... を試す。
  3. let_expr が let x = ... を試す。

サブ目標 30: 式全体への統合

関数に関する各パーサを、すべての式を扱う入口である expr に統合する。

(* expr : input -> (exp * input) option *)
and expr input =
  (let_rec_expr
   <|> named_fun_expr
   <|> let_expr
   <|> if_expr
   <|> fun_expr
   <|> comp_expr)
  input

この順序は、共通する接頭辞を持つ構文について、より具体的なものを先に試す方針による。

また、関数の構文を統合するには、次の変更も必要である。

  • primary_expr の選択肢に paren_expr を追加する。
  • paren_expr の括弧内を expr で解析する。
  • times_div_expr が primary_expr を呼んでいた箇所を app_expr に変更する。
  • fun_expr、named_fun_expr、let_rec_expr の本体を expr で解析する。
  • 互いに呼び出し合う式パーサを、let rec ... and ... による相互再帰として定義する。

相互再帰グループの全体像は、概略として次のようになる。

let rec primary_expr input =
  ...
and paren_expr input =
  ...
and app_expr input =
  ...
and times_div_expr input =
  ...
and plus_minus_expr input =
  ...
and comp_expr input =
  ...
and if_expr input =
  ...
and let_expr input =
  ...
and fun_expr input =
  ...
and named_fun_expr input =
  ...
and let_rec_expr input =
  ...
and expr input =
  ...

token、symbol_p、keyword_p、ident_p、return、let*、<|> など、式パーサより前に定義できる補助関数は、この相互再帰グループへ含める必要はない。

課題 4-2-7（関数の構文解析）

  • fun x -> x + 1 を解析し、Fun ("x", Plus (Var "x", IntLit 1)) が生成されることを確認しなさい。
  • f x y を解析し、左結合の App (App (Var "f", Var "x"), Var "y") が生成されることを確認しなさい。
  • f (x + 1) を解析し、App (Var "f", Plus (Var "x", IntLit 1)) が生成されることを確認しなさい。
  • (fun x -> x + 1) 3 を解析し、無名関数が関数の位置にある App が生成されることを確認しなさい。
  • let add x = x + 1 in add 3 を解析し、名前付き関数定義が Let と Fun の組合せへ変換されることを確認しなさい。
  • let rec f x = if x = 0 then 1 else x * f (x - 1) in f 5 を解析し、LetRec を根とする構文木が生成されることを確認しなさい。
  • 複数引数の名前付き関数定義を、入れ子になった Fun へ変換するパーサへ拡張しなさい(ヒント: =が来るまで引数をためておいて、List.fold_rightを使う)。

サブ目標 31: ASTの拡張

type exp =
  ...
  | Tuple of exp list
  | Empty
  | Cons of exp * exp
  | Head of exp
  | Tail of exp

Tuple は2個以上の要素を持つ組、Empty は空リスト、Cons はリストの先頭要素と残り、Head と Tail はリスト操作を表す。

サブ目標 32: 単なる括弧と組の区別

(e) は単なる括弧だが、(e1, e2) は組である。最初の式を読んだ直後にカンマがあるかどうかで区別する。

  • ミニ目標 32-1: 開き括弧と最初の式を読む。
  • ミニ目標 32-2: カンマがなければ閉じ括弧を読み、最初の式をそのまま返す。
  • ミニ目標 32-3: カンマがあれば、後続する式を一つ以上読む。
  • ミニ目標 32-4: 読み取った式の列から Tuple を作る。
(* paren_or_tuple_expr : input -> (exp * input) option *)
let paren_or_tuple_expr input =
  (let* _ = token (symbol_p "(") in
   let* first = expr in

   (let* _ = token (symbol_p ",") in
    let* second = expr in

    (* more : exp list -> input -> (exp list * input) option *)
    let rec more acc =
      (let* _ = token (symbol_p ",") in
       let* e = expr in
       more (e :: acc))
      <|> return (List.rev acc)
    in

    let* elements = more [second; first] in
    let* _ = token (symbol_p ")") in
    return (Tuple elements))

   <|>

   (let* _ = token (symbol_p ")") in
    return first))
  input

組の分岐を先に試す。カンマがなければその分岐は失敗し、同じ最初の入力から単なる括弧の分岐を試す。空の括弧 () を単位値として扱う場合は、最初の式を読む前に "()" を読む選択肢を追加する。

サブ目標 33: 空リスト

(* empty_list_expr : input -> (exp * input) option *)
let empty_list_expr input =
  (let* _ = token (symbol_p "[") in
   let* _ = token (symbol_p "]") in
   return Empty)
  input

空リストは2つの記号を順番に読むだけでよい。ただし、空でないリストも [ で始まるため、empty_list_expr と後述する list_expr は共通の接頭辞を持つ。

サブ目標 34: リストリテラル

[e1; e2; e3] は、内部的には e1 :: e2 :: e3 :: [] と同じ構造へ変換できる。

  • ミニ目標 34-1: 開き角括弧と最初の要素を読む。
  • ミニ目標 34-2: セミコロンと次の要素を、続く限り読む。
  • ミニ目標 34-3: 閉じ角括弧を読む。
  • ミニ目標 34-4: 要素列を右から Cons で畳み込む。
(* list_expr : input -> (exp * input) option *)
let list_expr input =
  (let* _ = token (symbol_p "[") in
   let* first = expr in

   (* elements : exp list -> input -> (exp list * input) option *)
   let rec elements acc =
     (let* _ = token (symbol_p ";") in
      let* e = expr in
      elements (e :: acc))
     <|> return (List.rev acc)
   in

   let* es = elements [first] in
   let* _ = token (symbol_p "]") in
   return
     (List.fold_right
        (fun e rest -> Cons (e, rest))
        es
        Empty))
  input

elements は効率よく先頭へ追加するため、途中では逆順に要素を蓄積する。終了時に List.rev で元の順へ戻す。その後、List.fold_right によって末尾の Empty から右向きに Cons を組み立てる。

サブ目標 35: 右結合の ::

:: は右結合である。したがって、加算で使った左結合のアキュムレータ処理をそのまま使ってはならない。

(* cons_expr : input -> (exp * input) option *)
let rec cons_expr input =
  (let* e1 = plus_expr in
   (let* _ = token (symbol_p "::") in
    let* e2 = cons_expr in
    return (Cons (e1, e2)))
   <|> return e1)
  input

右辺で cons_expr 自身を再帰的に呼ぶため、1 :: 2 :: [] は次のようになる。

Cons (IntLit 1,
  Cons (IntLit 2,
    Empty))

サブ目標 36: List.hd と List.tl

(* head_expr : input -> (exp * input) option *)
let head_expr input =
  (let* _ = token (keyword_p "List.hd") in
   let* e = primary_expr in
   return (Head e))
  input

(* tail_expr : input -> (exp * input) option *)
let tail_expr input =
  (let* _ = token (keyword_p "List.tl") in
   let* e = primary_expr in
   return (Tail e))
  input

List.hd と List.tl を一つのキーワードとして読むには、現在の識別子規則がピリオドを含まないことを利用できる。将来モジュール名やフィールド参照を一般化する場合は、List、.、hd を別々に読む設計へ変更する。

サブ目標 37: 優先順位への統合

空リスト、リストリテラル、組、List.hd、List.tl は基本式の選択肢へ追加する。一方、:: は加算より弱く、比較より強い階層として置く。

app_expr
    ↓
times_expr
    ↓
plus_expr
    ↓

  • (1) が Tuple ではなく IntLit 1 になることを確認しなさい。

  | PNil

サブ目標 39: 基本パターン

(* simple_pattern : input -> (pattern * input) option *)
let simple_pattern input =
  ((let* _ = token (symbol_p "_") in return PWildcard)
   <|> (let* n = token int_p in return (PInt n))
   <|> (let* _ = token (keyword_p "true") in return (PBool true))
   <|> (let* _ = token (keyword_p "false") in return (PBool false))
   <|> (let* x = token ident_p in return (PVar x)))
  input

ワイルドカードは値を束縛しない。変数パターンは一致した値をその名前へ束縛する。リテラルパターンは値が同じ場合だけ一致する。

サブ目標 40: 組とリストのパターン

組パターンは式の組と同様にカンマ区切りで読む。空リストパターンは []、コンスパターンは右結合の :: で読む。

(* empty_list_pattern : input -> (pattern * input) option *)
let empty_list_pattern input =
  (let* _ = token (symbol_p "[") in
   let* _ = token (symbol_p "]") in
   return PNil)
  input

(* tuple_pattern : input -> (pattern * input) option *)
let rec tuple_pattern input =
  (let* _ = token (symbol_p "(") in
   let* first = pattern in
   let* _ = token (symbol_p ",") in
   let* second = pattern in
   let rec more acc =
     (let* _ = token (symbol_p ",") in
      let* p = pattern in
      more (p :: acc))
     <|> return (List.rev acc)
   in
   let* ps = more [second; first] in
   let* _ = token (symbol_p ")") in
   return (PTuple ps))
  input

(* atomic_pattern : input -> (pattern * input) option *)
and atomic_pattern input =
  (empty_list_pattern <|> tuple_pattern <|> simple_pattern) input

(* pattern : input -> (pattern * input) option *)
and pattern input =
  (let* p1 = atomic_pattern in
   (let* _ = token (symbol_p "::") in
    let* p2 = pattern in
    return (PCons (p1, p2)))
   <|> return p1)
  input

サブ目標 41: 1本の節

(* match_case : input -> ((pattern * exp) * input) option *)
let match_case input =
  (let* p = pattern in
   let* _ = token (keyword_p "->") in
   let* e = expr in
   return (p, e))
  input

先頭の縦棒は最初の節では省略できるため、縦棒そのものは複数節を読む側で処理する方が、match_case の役割が単純になる。

サブ目標 42: 複数の節と match 式

(* match_expr : input -> (exp * input) option *)
let match_expr input =
  (let* _ = token (keyword_p "match") in
   let* target = expr in
   let* _ = token (keyword_p "with") in
   let* _ = token (symbol_p "|") <|> return "" in
   let* first = match_case in

   (* cases : (pattern * exp) list ->
              input -> ((pattern * exp) list * input) option *)
   let rec cases acc =
     (let* _ = token (symbol_p "|") in
      let* c = match_case in
      cases (c :: acc))
     <|> return (List.rev acc)
   in

   let* rest = cases [] in
   return (Match (target, first :: rest)))
  input

最初の節を必ず1本読んでから、| に続く節を繰り返し読む。これにより、節が1本もない match e with を成功させない。

課題 4-2-9（パターンマッチ）

  • match x with | 0 -> 1 | _ -> 2 をパースしなさい。
  • match xs with | [] -> 0 | x :: rest -> x をパースしなさい。
  • match pair with | (x, y) -> x + y の組パターンを追加しなさい。

11-1. 逐次実行

e1; e2 は低い優先順位を持つ右結合の構文として解析し、Seq (e1, e2) または Let ("_", e1, e2) へ変換できる。リストリテラルでもセミコロンを使うため、角括弧内部の要素区切りと通常の逐次実行を区別する必要がある。
