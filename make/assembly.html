アセンブラ

コード生成によって出力されたアセンブリを解析し、 疑似命令の展開、シンボル表の作成、ラベル解決、 静的データの配置を行って、仮想CPUが直接読み込める実行可能形式へ変換します。

  • アセンブリ
  • ↓ 構文解析・疑似命令展開・ラベル解決・静的データ配置
  • 実行可能形式

基本仕様では、仮想命令を固定長のビット列へ符号化しません。 アセンブラは、命令をOCamlのデータ型で表された命令配列へ変換します。 命令のバイトコード符号化、オブジェクト形式、リンカは発展仕様とします。

アセンブリプログラムの構文

アセンブリプログラムを P、 アセンブリ項目を u、 命令を I、 ディレクティブを D、 ラベルを L で表します。

構文 名称 説明
P ::= u1 ... un アセンブリプログラム アセンブリ項目を順番に並べたもの
u ::= I 命令 仮想CPUの基本命令またはアセンブラの疑似命令
u ::= L: ラベル定義 現在のコード位置またはデータ位置へ名前を付ける
u ::= D ディレクティブ セクション、静的データ、シンボル、 エントリポイントなどを指定する

字句要素

字句要素 構文 説明
識別子 英字またはアンダースコアで始まり、 英数字、アンダースコア、ピリオドが続く文字列 命令名、ディレクティブ名、シンボル名に使用する
ラベル L コードまたは静的データの位置を表す識別子
レジスタ r0 | r1 | ... | r15 仮想CPUの16本の物理レジスタ
10進整数 42、-42 10進表記の符号付き整数
16進整数 0x2a、-0x2a 16進表記の符号付き整数
2進整数 0b101010、-0b101010 2進表記の符号付き整数
文字列 "hello\n" ダブルクォートで囲んだ文字列リテラル
コメント ;から行末まで アセンブラが無視する説明文
改行 LFまたはCRLF 命令、ラベル、ディレクティブの区切り

整数リテラルのアンダースコア区切りを許可する場合は、 1_000_000のように数字の間だけで使用できるものとします。 解析後の値は符号付き64ビット整数の範囲内でなければなりません。

文字列のエスケープ

表記 文字
\\ バックスラッシュ
\" ダブルクォート
\n 改行
\r 復帰
\t 水平タブ
\0 ヌル文字
\xHH 2桁の16進数で指定した1バイト
\u{H...} Unicodeコードポイント

命令の一般構文

構文 説明
op オペランドを持たない命令
op a1 1個のオペランドを持つ命令
op a1, a2 2個のオペランドを持つ命令
op a1, a2, a3 3個のオペランドを持つ命令

オペランド

構文 名称 使用箇所
r レジスタ 演算、転送、アドレス、間接ジャンプ
i 整数即値 即値読込み、即値演算、trap番号、データ
L ラベル 直接ジャンプ、直接呼出し、アドレス取得、データ参照
o(r) メモリアドレス レジスタ rを基底とし、 oワードを加えたアドレス

メモリアドレスとメモリオフセットはワード単位です。 たとえば 2(r5)は、 r5が示すアドレスから2ワード先を表します。

セクション

ディレクティブ 効果
.text 現在のセクションをコード領域へ変更する。 以降には命令とコードラベルを配置する
.data 現在のセクションを静的データ領域へ変更する。 以降にはデータとデータラベルを配置する

最初のセクション指定より前に命令またはデータが現れた場合は、 アセンブルエラーとします。 ラベルは現在選択されているセクションに属します。

シンボルディレクティブ

ディレクティブ 効果 基本仕様での扱い
.global L ラベルLを外部へ公開する 単一ファイルでも受理するが、実質的な効果はない
.extern L 別の単位で定義されるシンボルを宣言する ランタイムシンボルとして既知でなければ、 単一ファイルのアセンブル時に未解決シンボルエラーとする
.entry L 仮想CPUが最初に実行するコードラベルを指定する プログラム全体で高々1回だけ指定できる

.entryがない場合は、 mainをエントリポイントとして使用します。 mainも定義されていない場合はエラーとします。

静的データディレクティブ

ディレクティブ 配置するデータ データ位置の変化
.word i 符号付き64ビット整数を1ワード配置する 1ワード進む
.word L コードまたはデータラベルのアドレスを1ワード配置する 1ワード進む
.zero n nワードを0で初期化する nワード進む
.string s UTF-8へ変換した文字列を、 ランタイムの文字列表現に従って配置する 文字列の静的表現に必要なワード数だけ進む
.align n 現在位置が nワード境界になるまで0を配置する 必要なパディング分だけ進む

.zeroのワード数は0以上でなければなりません。 .alignの境界は1以上の2の冪とします。

文字列の静的表現

.stringは、単なるバイト列ではなく、 ランタイムが文字列として認識できる静的ブロックを生成します。 基本仕様では次の構造を使用します。

位置 内容
ヘッダ 文字列タグと文字列ブロックのワード数
フィールド0 UTF-8のバイト長を表すタグ付き整数
フィールド1以降 UTF-8バイト列を8バイトずつ格納したワード
末尾 不足するバイトを0で埋める

データラベルはフィールド0の位置を指し、 ヘッダはその1ワード前に配置します。 これにより、静的文字列を通常のヒープブロックと同じ規則で参照できます。

基本命令

基本命令は、仮想CPUが直接実行する命令です。 アセンブラは命令名、オペランド数、オペランドの種類を検査し、 対応する命令値を生成します。

la rd, L コードラベルならLoadCodeAddress (rd, code_address(L))、 データラベルならLoadDataAddress (rd, data_address(L)) ラベルLが指すアドレスを取得する
mov rd, rs Move (rd, rs) rsの値をrdへコピーする

add rd, rs1, rs2 Add (rd, rs1, rs2) 64ビット加算

rem rd, rs1, rs2 Rem (rd, rs1, rs2) 符号付き剰余。除数が0の場合は実行時エラー

比較

アセンブリ 実行可能形式 意味
seq rd, rs1, rs2 SetEqual (rd, rs1, rs2) 等しければ生の整数1、異なれば生の整数0を格納する

比較命令が生成する0と1は、生の機械整数です。 ソース言語の真偽値として利用する場合は、 コード生成側がタグ付けを行います。

    data = assembled_data;

アセンブラの中間表現

構文解析直後は、ラベル参照を未解決のまま保持します。 命令、ラベル、ディレクティブを次のような構文木で表現できます。

種類 主な内容
Instruction 命令名、オペランド列、ソース位置
Label ラベル名、ソース位置
Directive ディレクティブ名、引数列、ソース位置
Register 0以上15以下のレジスタ番号
Immediate 符号付き64ビット整数
Symbol 未解決のコードラベルまたはデータラベル
Memory ワードオフセットと基底レジスタ

第1パス

第1パスでは、疑似命令展開後のコード位置とデータ位置を計算し、 すべての定義済みラベルをシンボル表へ登録します。

アセンブリ項目 第1パスの処理 位置の変化
.text 現在のセクションをコードへ変更する 変化しない
.data 現在のセクションをデータへ変更する 変化しない
コードセクション内のラベル 現在のコード位置を CodeSymbolとして登録する 変化しない
データセクション内のラベル 現在のデータ位置を DataSymbolとして登録する 変化しない
基本命令 オペランドの形を検査する コード位置を1進める
疑似命令 展開後の基本命令数を求める 展開後の命令数だけコード位置を進める
.word データセクションであることを検査する データ位置を1進める
.zero n nが0以上であることを検査する データ位置をn進める
.string s 文字列の静的表現に必要なワード数を求める 必要なワード数だけデータ位置を進める
.align n 現在のデータ位置を境界nへ切り上げる パディング分だけデータ位置を進める
.entry L エントリポイント候補としてラベル名を記録する 変化しない

シンボル表

シンボル値 意味
CodeSymbol p 命令配列の位置 pを指すコードラベル
DataSymbol o 静的データ領域先頭から oワード離れたデータラベル
ExternalSymbol name 発展　リンク時に解決する外部シンボル

同じラベル名を複数回定義してはなりません。 コードラベルとデータラベルも同じ名前空間を使用します。

第2パス

第2パスでは、命令と静的データを実際に生成し、 すべてのラベル参照をシンボル表の値へ置き換えます。

アセンブリ項目 第2パスの変換 説明
ラベル定義 出力しない 位置はすでにシンボル表へ記録されている
基本命令 対応する命令値を命令配列へ追加する レジスタと即値を検査済みの値へ変換する
疑似命令 展開後の基本命令値を順番に追加する 疑似命令自体は実行可能形式へ残さない
jump Lなど ラベル Lをコード位置へ置き換える データラベルを指定した場合はエラー
la rd, L シンボルの種類に応じて、 コードアドレスまたはロード後のデータアドレスを生成する コードとデータの両方を参照できる
.word i 整数iをデータ配列へ追加する 64ビットのビット列を保存する
.word L ラベル Lのアドレスをデータ配列へ追加する コードアドレスまたはデータアドレスを格納する
.zero n 0をnワード追加する 予約領域を0で初期化する
.string s 文字列のヘッダ、長さ、UTF-8データを追加する ラベルはフィールド0を指す
.align n 必要な数の0ワードを追加する データ位置を指定境界へ整列する
.entry L コード位置を実行可能形式のentryへ設定する データラベルを指定した場合はエラー

コードアドレスとデータアドレス

仮想CPUでは、コードアドレスは命令配列の添字、 データアドレスはVMメモリ内のワードアドレスです。 両者は64ビット値としてレジスタや静的データへ格納できますが、 使用できる命令が異なります。

アドレス 表現 使用命令
コードアドレス 命令配列内の0以上の添字 jumpr、jalr
データアドレス VMメモリ内のワード位置 load、store

コードアドレスを loadや storeへ使用した場合、 またはデータアドレスを jumprや jalrへ使用した場合は実行時エラーとします。 OCaml実装では、検査のためにアドレスの種類を別の型で保持しても構いません。

静的データのロード時再配置

データラベルは、第1パスでは静的データ領域内の相対位置として記録します。 実際のメモリアドレスは、VMが実行可能形式をロードするときに決まります。

値 ロード時の変換
データラベルの相対位置o data_base + o
コードラベルの位置p 命令配列の位置pをそのまま使用する
静的データ内のデータラベル参照 ロード時にデータ基底アドレスを加える
静的データ内のコードラベル参照 命令配列内の位置をコードアドレスとして格納する

実行可能形式

基本仕様の実行可能形式は、 ラベル解決済みの命令配列、静的データ、 データ内のアドレス情報、エントリポイントを持ちます。

フィールド 内容
code ラベル解決済みの基本命令配列
data 静的データの64ビットワード配列
data_relocations データ内でコードアドレスまたはデータアドレスとして 解釈すべき位置
entry 最初に実行する命令配列内の位置
globals 公開シンボル名と解決済み位置の対応 
type executable = {
    code : instruction array;
    data : int64 array;
    data_relocations : relocation array;
    entry : int;
    globals : symbol_table;
}

分割コンパイルを実装しない段階では、 globalsと未解決の外部再配置を省略できます。 ただし、静的データ内のデータアドレスをロード時に補正するため、 必要な再配置情報は保持します。

命令のOCaml表現

type register = int

type instruction =
    | Li of register * int64
    | LoadCodeAddress of register * int
    | LoadDataAddress of register * int
    | Move of register * register
    | Add of register * register * register
    | Sub of register * register * register
    | Mul of register * register * register
    | Div of register * register * register
    | Rem of register * register * register
    | AddImmediate of register * register * int64
    | BitAnd of register * register * register
    | BitOr of register * register * register
    | BitXor of register * register * register
    | BitNot of register * register
    | ShiftLeft of register * register * register
    | ShiftRightLogical of register * register * register
    | ShiftRightArithmetic of register * register * register
    | SetEqual of register * register * register
    | SetLessThan of register * register * register
    | Load of register * register * int
    | Store of register * register * int
    | Jump of int
    | JumpRegister of register
    | BranchZero of register * int
    | BranchNonZero of register * int
    | JumpAndLink of register * int
    | JumpAndLinkRegister of register * register
    | Trap of int

レジスタ番号は0以上15以下でなければなりません。 コード位置とメモリオフセットのOCaml型は、 実装上必要な最大サイズに応じて intまたは int64を使用します。

アセンブラ全体の処理

段階 入力 処理 出力
1. 字句解析 アセンブリテキスト 識別子、整数、文字列、記号、改行へ分割する トークン列
2. 構文解析 トークン列 命令、ラベル、ディレクティブを構築する アセンブリ構文木
3. 疑似命令展開 アセンブリ構文木 疑似命令を基本命令列へ変換する 基本命令だけを含む構文木
4. 第1パス 展開済み構文木 コード位置とデータ位置を計算し、ラベルを登録する シンボル表と各セクションのサイズ
5. 第2パス 構文木とシンボル表 ラベルを解決し、命令配列とデータを生成する 未ロードの実行可能形式
6. 検査 未ロードの実行可能形式 命令、アドレス、エントリポイント、データサイズを検査する 検査済み実行可能形式

ランタイムシンボル

コード生成器が runtime_allocや runtime_print_intなどを通常の関数として呼び出す場合、 アセンブラは対応するランタイムコードを同じプログラムへ結合するか、 既知のランタイムシンボルとして解決します。

方式 処理 基本仕様での採用
ランタイムアセンブリ結合 ランタイム関数を通常のアセンブリとして ユーザープログラムと同時にアセンブルする 採用する
既知シンボルからtrapへ変換 一部のランタイム関数呼出しを、 対応する trap命令を含むラッパーへ解決する 入出力、終了、メモリ確保などに使用できる
外部リンク 発展　ランタイムを別オブジェクトとしてリンクする 分割コンパイル導入後に使用する

trap番号

命令 処理 引数 戻り値
trap 0 プログラムの終了 r1の終了コード 戻らない
trap 1 整数の出力 r1のタグ付き整数 r1に単位値
trap 2 文字の出力 r1のタグ付き文字コード r1に単位値
trap 3 文字の入力 なし r1に読み込んだ文字
trap 4 文字列の出力 r1の文字列ポインタ r1に単位値
trap 5 1行の入力 なし r1に文字列ポインタ
trap 6 メモリの確保 r1の生のワード数 r1に確保領域の先頭アドレス
trap 7 実行時エラーの報告 r1のエラー番号またはエラー値 戻らない

アセンブルエラー

分類 条件 報告する情報
字句エラー 不正な文字、閉じていない文字列、不正なエスケープ ファイル名、行、列、不正な字句
構文エラー 命令、ラベル、ディレクティブの構文が正しくない 行、列、期待した構文、実際のトークン
未知の命令 命令セットに存在しない命令名を使用した 命令名とソース位置
オペランドエラー オペランド数または種類が命令仕様と一致しない 命令名、期待した形式、実際のオペランド
レジスタエラー r0からr15以外を指定した レジスタ名とソース位置

実行可能形式の検査

  • エントリポイントが命令配列の範囲内にある
  • 各命令のレジスタ番号が0以上15以下である
  • 各直接ジャンプ先と直接呼出し先が命令配列の範囲内にある
  • 各命令のオペランドが命令仕様と一致している
  • 静的データがVMのメモリへ収まる
  • 静的データ内の再配置位置がデータ配列の範囲内にある
  • コード再配置がコード位置を指している
  • データ再配置が静的データ内の位置を指している
  • 未知のtrap番号を基本仕様の実行可能形式へ含めていない

発展　オブジェクト形式

フィールド 内容
code 発展　ラベルの一部が未解決の命令列
data 発展　静的データ

発展　リンカ

段階 処理
1 複数のオブジェクトのコード領域とデータ領域を結合する
2 公開シンボルを一つの大域シンボル表へ登録する
3 各外部シンボルを大域シンボル表から解決する
4 結合後のコード位置とデータ位置に基づいて再配置を適用する
5 エントリポイントを決定する
6 最終的な実行可能形式を生成して検査する

発展　命令の符号化

基本仕様では命令をOCamlの代数的データ型として保持します。 固定長または可変長バイトコードを導入する場合は、 命令コード、レジスタ番号、即値、オフセット、 コードアドレスのビット配置を別途定義します。

必要な仕様 内容
命令形式 命令コードと各オペランドのビット幅
即値形式 符号拡張、ゼロ拡張、範囲外即値の展開方法
アドレス形式 絶対アドレス、相対アドレス、再配置形式
デコード 仮想CPUがバイト列から命令を復元する規則
互換性 実行可能形式のバージョン番号と検査規則

アセンブル後に成立する条件

  • すべての疑似命令が基本命令へ展開されている
  • 命令配列にラベル定義、ディレクティブ、コメントが残っていない
  • すべてのコードラベル参照が命令配列内の位置へ解決されている
  • すべてのデータラベル参照が静的データ内の位置または再配置情報へ変換されている
  • 各命令のオペランド数と種類が命令仕様に一致している
  • すべてのレジスタ番号が0以上15以下である
  • すべての整数即値が許容範囲内にある
  • 静的データがワード配列として配置されている
  • 文字列がランタイムの静的文字列表現へ変換されている
  • エントリポイントが一つの有効なコード位置へ解決されている
  • 実行可能形式がVMの事前検査を通過できる
  • 発展　外部シンボルがリンカによって解決されている
  • 発展　すべてのリンク時再配置が適用されている

次の段階との関係

仮想CPUは、アセンブラが生成した実行可能形式をロードし、 静的データをメモリへ配置してから、 エントリポイントにプログラムカウンタを設定します。

ロード処理 内容
命令列の設定 executable.codeを仮想CPUのコード領域へ設定する
静的データの配置 executable.dataをメモリの静的データ領域へコピーする
再配置 データ基底アドレスが必要な静的データ参照を補正する
エントリポイント pcをexecutable.entryへ設定する
レジスタ r0からr13と r15を0へ初期化する
スタック r14をスタック領域の終端アドレスへ設定する
実行開始 haltedを偽にして命令実行ループを開始する
