トークン列

字句解析は、UTF-8のソースコードを、構文解析器が処理できるトークン列へ変換する処理です。 空白とコメントを読み飛ばし、予約語、識別子、リテラル、演算子、区切り記号を認識します。 各トークンには、エラー報告に使用するソース位置を付与します。

  • UTF-8ソースコード
  • ↓ 字句解析
  • 位置情報付きトークン列
  • ↓ 構文解析
  • 抽象構文木

入力と出力

項目内容
入力UTF-8で符号化されたソースファイル
出力位置情報を持つトークンの列と終端トークンEOF
読み飛ばすもの空白、改行、コメント
失敗不正文字、閉じていないコメント、閉じていない文字列、不正なエスケープ、不正な数値

トークンの内部表現

type position = {
    offset : int;
    line : int;
    column : int;
}

type span = {
    start_pos : position;
    end_pos : position;
}

type located_token = {
    token : token;
    span : span;
}

offsetはファイル先頭からのバイト位置、lineとcolumnは1から始まる表示位置とします。 end_posはトークン直後の位置を指す半開区間として扱います。

識別子

分類字句形式トークン主な用途
小文字識別子小文字または_で始まり、英数字、_、'が続くLIDENT(name)値名、型名、フィールド名
大文字識別子大文字で始まり、英数字、_、'が続くUIDENT(name)コンストラクタ名、モジュール名、モジュール型名
型変数'の後に小文字識別子TYVAR(name)'a、'valueなどの型変数
ワイルドカード_だけUNDERSCOREワイルドカードパターン、発展構文の匿名型引数

字句解析器は、LIDENTが予約語表に存在する場合、識別子ではなく対応する予約語トークンを返します。 コンストラクタ、モジュール、モジュール型の区別は字句解析では行わず、構文解析と名前解決で決定します。

識別子として使用できる文字

位置基本仕様例
小文字識別子の先頭aからzまたは_x、value、_tmp
大文字識別子の先頭AからZSome、Tree、String
継続文字ASCII英数字、_、'map2、value'、Tree_node
型変数名小文字から始まる識別子'a、'key

初期実装では識別子をASCIIに限定します。 UTF-8の日本語識別子などを許可する場合は、Unicode識別子の正規化方式と文字分類を別途仕様化します。

整数リテラル

形式例トークン
10進整数0、42、1000000INT(value)
区切り付き10進整数1_000_000INT(1000000)
負の整数-42MINUS INT(42)

符号は数値トークンへ含めません。 -42は単項マイナスと整数リテラルの二つのトークンとして扱います。 これにより、二項減算と単項マイナスの区別を構文解析で統一して処理できます。

整数の区切り文字

入力結果
1_000有効。値は1000
_1000整数ではなく識別子として認識する
1000_不正な数値リテラル
1__000不正な数値リテラル

浮動小数点リテラル

形式例トークン
小数点形式0.0、3.14FLOAT(value)
指数形式1e3、1.5e-2、2E+8FLOAT(value)
区切り付き1_000.25、1.0e1_0区切りを除去して変換する
負の浮動小数点数-3.14MINUS FLOAT(3.14)

1.はFLOAT(1.0)ではなく、INT(1)とDOTとして扱います。 浮動小数点リテラルの小数点形式では、小数点の後に少なくとも一桁を必要とします。 これにより、修飾名やフィールド参照との競合を避けます。

数値の範囲

種類規則
整数字句解析時に任意精度の文字列表現を保持し、対象のint範囲を超える場合は範囲外エラーとする
浮動小数点数IEEE 754倍精度へ変換し、オーバーフローまたは不正形式を字句エラーとする
nan、infinity通常の識別子として扱い、浮動小数点リテラルにはしない

文字リテラル

形式例結果
通常文字'a'CHAR('a')
空白文字' 'CHAR(' ')
エスケープ文字'\n'改行文字
Unicode文字'あ'Unicodeスカラー値一つ

文字リテラルは、一つのUnicodeスカラー値または一つのエスケープ列だけを含みます。 空文字、複数文字、改行を直接含む文字リテラルはエラーです。

文字列リテラル

形式例結果
空文字列""STRING("")
通常文字列"hello"STRING("hello")
エスケープを含む文字列"a\nb"改行文字を含む文字列
Unicode文字列"こんにちは"UTF-8として読み取り、内部文字列表現へ変換する

通常の文字列リテラルに改行を直接含めることはできません。 改行は\nで表します。 生文字列と複数行文字列は基本仕様に含めません。

最長一致

同じ先頭文字を持つトークンは、最も長く一致する字句を優先します。

入力先頭優先順位
<<-、<=、<>を先に試し、該当しなければ<
>>=を先に試し、該当しなければ>
:::、:=を先に試し、該当しなければ:
-->、-.を先に試し、該当しなければ-
++.を先に試し、該当しなければ+
*コメント開始(*は(の処理で認識し、*.を先に試す
//.を先に試し、該当しなければ/
|||、|]を先に試し、該当しなければ|
[[|を先に試し、該当しなければ[
&&&だけを有効とし、単独の&はエラー

空白

文字処理
半角空白読み飛ばす
水平タブ読み飛ばし、列番号を次のタブ位置へ進める

改行は文の終端トークンにはなりません。 宣言や式の境界は構文によって決定します。

単項演算子と二項演算子

字句解析器は、-、-.、!が単項か二項かを判定しません。 同じトークンを返し、構文解析器が出現位置から判定します。

ソーストークン列構文上の意味
-xMINUS LIDENT("x")整数の単項マイナス
x - yLIDENT("x") MINUS LIDENT("y")整数減算
-.xMINUS_DOT LIDENT("x")浮動小数点の単項マイナス
x -. yLIDENT("x") MINUS_DOT LIDENT("y")浮動小数点減算
!rBANG LIDENT("r")参照読出し

字句解析規則の優先順位

優先順位規則
1空白とコメントを読み飛ばす
2文字列リテラルと文字リテラルを認識する
3数値リテラルを最長一致で認識する
4識別子を認識し、予約語表を検索する
5複数文字の演算子と区切り記号を最長一致で認識する
6単一文字の演算子と区切り記号を認識する
7どの規則にも一致しない文字を字句エラーにする

単一引用符の曖昧性

単一引用符は文字リテラルと型変数の両方に使用します。 次の規則で区別します。

入力形式結果
'a'閉じる単一引用符があるためCHAR('a')
'\n'一つのエスケープと閉じる引用符があるためCHAR('\n')
'a閉じる引用符がなく型変数名として有効なためTYVAR("a")
'valueTYVAR("value")
''空の文字リテラルとしてエラー
'ab'複数文字の文字リテラルとしてエラー

字句解析後に成立する条件

  • コメントと空白が構文上のトークン列から除かれている
  • すべてのトークンが元ソース上の半開区間を持つ
  • トークンの位置範囲が入力順に単調増加している
  • 予約語がLIDENTとして残っていない
  • 小文字識別子、大文字識別子、型変数が区別されている
  • 整数、浮動小数点数、文字、文字列が内部値へ変換されている
  • 単項マイナスの符号が数値リテラルへ取り込まれていない
  • 複数文字の演算子が最長一致で一つのトークンになっている
  • コメントの入れ子が正しく閉じている
  • 文字列と文字のエスケープが検証されている
  • 不正なUnicodeスカラー値がトークン値へ入っていない
  • 改行形式の違いが位置情報へ正しく反映されている
  • トークン列の末尾に一つだけEOFがある
  • 構文上の文脈を必要とする区別が字句解析で誤って確定されていない
