レジスタ割当てとコード生成

仮想レジスタ中間表現に生存変数解析とレジスタ割当てを行い、 各仮想レジスタを物理レジスタまたはスタックスロットへ配置します。 その後、spill処理、呼出し規約の具体化、スタックフレーム配置、 基本ブロックの線形化を行い、アセンブリを生成します。

  • 仮想レジスタ中間表現
  • ↓ 生存変数解析・レジスタ割当て・spill
  • 物理レジスタ中間表現
  • ↓ 呼出し規約の具体化・スタックフレーム配置・線形化
  • アセンブリ

レジスタ割当てとコード生成は、関数ごとに実行します。 静的データと外部関数宣言は保持し、 各関数の仮想レジスタ、基本ブロック、通常命令、終端命令だけを具体化します。

物理レジスタ中間表現のプログラム

物理レジスタ中間表現のプログラムを P、 外部関数宣言を X、 静的データを D、 物理レジスタ関数を F で表します。

構文 名称 説明
P ::= X1 ... Xl D1 ... Dm F1 ... Fn 物理レジスタプログラム 外部関数宣言、静的データ、および物理レジスタへ割り当てられた 関数定義の集合

物理レジスタ関数の構文

物理レジスタ関数は、入口ブロック、基本ブロックの集合、 スタックフレーム情報、使用するcallee-saveレジスタの集合を持ちます。

構文 名称 説明
F ::= function f entry Lentry frame frame { B1 ... Bn } 物理レジスタ関数 物理レジスタ命令、スタック操作、呼出し処理を含む 基本ブロックの集合

基本ブロックの構文

構文 名称 説明
B ::= L: I1 ... In T 物理レジスタ基本ブロック ラベル、物理レジスタ通常命令列、および終端命令からなる

物理レジスタ

レジスタ 用途 レジスタ割当てでの扱い
r0 常に0を保持するゼロレジスタ 通常の値には割り当てない
r1からr4 第1引数から第4引数。r1は戻り値にも使用する 呼出し規約用として予約する
r5からr9 caller-saveの汎用レジスタ 呼出しをまたがない値へ優先的に割り当てる
r10からr12 callee-saveの汎用レジスタ 呼出しをまたいで生存する値へ優先的に割り当てる
r13 クロージャ環境ポインタ 通常の値には割り当てない
r14 スタックポインタ 通常の値には割り当てない
r15 戻りアドレス 通常の値には割り当てない

基本仕様では r5から r12までを割当て候補とします。 spill処理専用の一時レジスタを予約する場合は、 予約したレジスタを割当て候補から除外します。

割当て先

仮想レジスタ vの割当て先を loc(v) と表します。 

loc(v) ::= register(r) | stack(s)
割当て先 意味
register(r) 仮想レジスタの値を物理レジスタ rへ保持する
stack(s) 仮想レジスタの値を抽象スタックスロット sへ保持する

生存変数解析

ある命令位置より後で値が使用される可能性がある場合、 その値を保持する仮想レジスタは、その位置で生存しています。 各命令について使用集合と定義集合を求めます。

集合 定義
use(I) 命令Iが読み出す仮想レジスタの集合
def(I) 命令Iが新しい値を書き込む仮想レジスタの集合
live_in(I) 命令Iの直前で生存する仮想レジスタの集合
live_out(I) 命令Iの直後で生存する仮想レジスタの集合 
live_in(I) =
    use(I) ∪ (live_out(I) - def(I))

live_out(B) =
    後続ブロック S について live_in(S) の和集合

ループを含む場合は、すべての生存集合が変化しなくなるまで 制御フローグラフを反復して解析します。

命令の使用集合と定義集合

生存区間

各仮想レジスタについて、値が定義されてから最後に使用されるまでの 命令位置を生存区間として求めます。 生存区間が重なる仮想レジスタは、 同じ物理レジスタを同時に使用できません。

情報 意味
start(v) 仮想レジスタvが最初に定義または必要になる位置
end(v) 仮想レジスタvが最後に生存する位置
crosses_call(v) 生存区間内に関数呼出しが存在するかどうか
is_gc_root(v) セルフホスト後仮想レジスタがGCで追跡すべき値を保持するかどうか

分岐やループを含む場合、単純な命令番号による一つの区間は、 実際の生存範囲より広くなることがあります。 基本実装では、安全側に広い区間を使用します。

線形走査レジスタ割当て

基本実装では、線形走査法を使用します。 生存区間を開始位置順に処理し、 終了した区間が使用していた物理レジスタを再利用します。

段階 処理
1 各仮想レジスタの生存区間を求める
2 生存区間を開始位置の昇順に並べる
3 現在位置より前に終了した区間をactive集合から除去する
4 空いている物理レジスタを現在の区間へ割り当てる
5 空きがない場合は現在またはactive集合内の区間をspillする
6 決定した割当て先をloc(v)へ記録する

呼出しをまたいで生存する値には r10から r12までのcallee-saveレジスタを優先します。 呼出しをまたがない値には r5から r9までのcaller-saveレジスタを優先します。

利用できる物理レジスタがない場合は、 終了位置が最も遠い区間をspill候補とします。 現在の区間の終了位置がspill候補より遠い場合は、 現在の区間を直接spillできます。

レジスタ割当てとコード生成

仮想レジスタプログラム Pのレジスタ割当てを R⟦P⟧ と表します。 命令の各入力オペランドを物理レジスタへ用意し、 命令結果を物理レジスタまたはspillスロットへ保存します。

並列コピー

関数引数、戻り値、関数入口の仮引数を移動するときは、 複数のコピーを同時に行う並列コピーとして扱います。 コピー元を上書きしない順序へ並べ替え、 循環がある場合だけ一時領域を使用します。

mov r2, temporary
物理レジスタとスタックスロットの循環 一時レジスタまたは専用の一時スタックスロットで循環を切る
コピー元とコピー先が同じ コピーを削除する

スタックフレーム

スタックフレームは、保存領域、spill領域、 caller-save領域、一時領域、呼出し用引数領域から構成します。

領域 内容
戻りアドレス保存領域 関数入口時のr15
callee-save保存領域 関数内で使用するr10からr12
spill領域 物理レジスタへ割り当てられなかった仮想レジスタ
caller-save保存領域 関数呼出しをまたいで保持するcaller-saveレジスタ
並列コピー一時領域 レジスタだけでは循環を解消できない並列コピーに使用する
呼出し用引数領域 現在の関数が行う呼出しの第5引数以降を配置する
GCルート情報 セルフホスト後GCセーフポイントでポインタを保持するスロットを記録する 
frame_size =
    saved_return_address_words
    + saved_callee_register_words
    + spill_slot_words
    + caller_save_slot_words
    + temporary_slot_words
    + outgoing_argument_words
    + padding_words

フレーム全体は、VMの呼出し規約が要求する境界へ整列します。 スタックスロットは r14からのワード単位オフセットへ変換します。

保存するcallee-saveレジスタr saved_offset(r)(r14)

第5引数以降 outgoing_argument_offset(i)(r14)

基本ブロックの線形化

物理レジスタ中間表現の基本ブロックを、 ラベル付きの一列の命令列へ並べます。 入口ブロックから到達可能なブロックだけを配置します。

物理レジスタ中間表現 アセンブリ命令列 説明
基本ブロックの集合 入口ブロックから選択した順番に並べたラベル付き命令列 基本実装では深さ優先順で配置する
branch r, L_true, L_false 
brnz r, L_true
jump L_false
 一方の分岐先が直後にある場合は、 条件を反転して無条件ジャンプを一つ削除できる
直後のブロックへのjump 命令を削除する 実行はそのまま次のラベルへ進む
到達不能な基本ブロック 出力しない 入口ブロックから到達できないコードを除去する
複数の前任ブロックを持つブロック ラベルを保持する すべての分岐元が同じラベルを参照する

物理レジスタ中間表現の検査

  • すべての仮想レジスタが除去されている
  • 使用される物理レジスタがr0からr15の範囲にある
  • r0への書込み結果を使用していない
  • r13、r14、r15の予約用途が守られている
  • すべてのspillスロットに具体的なフレームオフセットがある
  • 同一命令で必要な一時レジスタ数が予約数を超えていない
  • 各基本ブロックが一つの終端命令を持つ
  • すべての分岐先ラベルが同じ関数内に存在する
  • 関数呼出しの引数数と配置が呼出し規約に従っている
  • 戻り値がr1へ配置されている
  • 通常の関数出口でcallee-saveレジスタとr15が復元される
  • 通常の関数出口でr14が入口時の値へ戻る
  • 末尾呼出しの前に現在のスタックフレームが安全に破棄される
  • 間接呼出しと間接末尾呼出しでコードアドレスがフレーム破棄前に保護される
  • 並列コピーに循環がある場合、一時レジスタまたは一時スロットが使用される
  • セルフホスト後GCセーフポイントで生存するポインタの位置が記録されている

変換後に成立する条件

  • すべての仮想レジスタが物理レジスタまたはスタックスロットへ割り当てられている
  • 同時に生存する二つの値が同じ物理レジスタへ不正に割り当てられていない
  • spillされた値の各使用前に必要なreloadが挿入されている
  • spillされた値の各定義後に必要なstoreが挿入されている
  • 呼出しをまたいで生存するcaller-save値が保護されている
  • 使用するcallee-saveレジスタが関数入口と出口で保存および復元されている
  • 関数の仮引数が呼出し規約上の到着位置から割当て先へ移動されている
  • 関数呼出しの実引数が引数レジスタまたはスタック引数領域へ配置されている
  • 関数の戻り値がr1を通して返されている
  • 各関数のスタックフレームサイズと各スロットのオフセットが確定している
  • 通常の関数出口が共通出口ブロックへ統合されている
  • 末尾呼出しが新しいスタックフレームを作らないジャンプへ変換されている
  • 基本ブロックがラベル付きの線形な命令列へ変換されている
  • 直後のブロックへの不要なジャンプが削除されている
  • 到達不能な基本ブロックが出力されていない
  • switchが比較列、比較木、またはジャンプテーブルへ変換されている
  • 外部関数宣言、静的データ、コードラベルがアセンブリへ出力されている

次の段階との関係

出力されたアセンブリは、アセンブラによって解析され、 ラベル解決、命令エンコード、静的データ配置を経て 実行可能形式へ変換されます。

  • アセンブリを命令、レジスタ、即値、ラベルへ構文解析する
  • 各命令のオペランド数と範囲を検査する
  • .textと.dataの配置を決定する
  • コードラベルとデータラベルのアドレスを決定する
  • 外部シンボルと再配置情報を処理する
  • 仮想CPUが読み込める実行可能形式を生成する
