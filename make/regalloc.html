レジスタ割当てとコード生成

仮想レジスタ中間表現に生存変数解析とレジスタ割当てを行い、 仮想レジスタを物理レジスタまたはスタックスロットへ配置します。 その後、スタックフレームを確定し、基本ブロックを線形化して アセンブリを生成します。

  • 物理レジスタ中間表現
    ↓ スタックフレーム配置・線形化
  • アセンブリ

レジスタ割当てとコード生成の規則

R[P]は、 仮想レジスタ中間表現のプログラムPを 物理レジスタ中間表現へ変換した結果を表します。

各仮想レジスタには、物理レジスタまたはスタックスロットを割り当てます。 loc(v)は、 仮想レジスタvの割当て先を表します。 

loc(v) ::= register(r) | stack(s)

生存変数解析

ある命令位置より後で値が使用される可能性があるとき、 その値を保持する仮想レジスタは、その位置で生存しているといいます。 

li  v1, 10
li  v2, 20
add v3, v1, v2
mul v4, v3, v3
return v4

v1とv2は、addまで生存しています。 addの後では使用されないため、その後は同じ物理レジスタを 別の値に再利用できます。

useとdef

各命令について、使用する仮想レジスタと定義する仮想レジスタを求めます。

use(I) 命令Iが読み出す仮想レジスタ
def(I) 命令Iが新しい値を書き込む仮想レジスタ
命令 use def
li v1, 10 {} {v1}
mov v1, v2 {v2} {v1}
add v1, v2, v3 {v2, v3} {v1}
load v1, 0(v2) {v2} {v1}
store v1, 0(v2) {v1, v2} {}
branch v1, L1, L2 {v1} {}
return v1 {v1} {}

命令の前後の生存集合

live_in(I) 命令Iの直前で生存する仮想レジスタ
live_out(I) 命令Iの直後で生存する仮想レジスタ 
live_in(I) =
    use(I) ∪ (live_out(I) - def(I))

通常命令のlive_outは、次の命令のlive_inです。 基本ブロックの終端では、すべての後続ブロックの live_inの和集合を使用します。 

live_out(B) =
    後続ブロックSについて live_in(S) の和集合

ループを含む場合は、生存集合が変化しなくなるまで 制御フローグラフを繰り返し解析します。

生存区間

各仮想レジスタについて、値が定義されてから最後に使用されるまでの範囲を 生存区間として求めます。 

v1: [0, 3]
v2: [1, 3]
v3: [3, 5]
v4: [5, 6]

生存区間が重なる仮想レジスタは、同じ物理レジスタを同時に使用できません。

分岐やループを含む場合、単純な命令番号の区間は実際の生存範囲より 広くなることがあります。基本実装では安全側に広い区間を使用します。

割当て可能な物理レジスタ

仮想CPUは16本の物理レジスタを持ちますが、 すべてを通常の値へ割り当てられるわけではありません。

レジスタ レジスタ割当てでの扱い
r0 常に0であるため割り当てない
r1～r4 引数と戻り値に使用する
r5～r9 caller-saveの汎用レジスタ
r10～r12 callee-saveの汎用レジスタ
r13 クロージャポインタとして予約する
r14 スタックポインタとして予約する
r15 戻りアドレスとして予約する

基本実装では、通常の値へ割り当てるレジスタを r5からr12までとします。

レジスタ割当て

各仮想レジスタを、物理レジスタまたはスタックスロットへ割り当てます。 

v0 -> r5
v1 -> r6
v2 -> stack slot 0
v3 -> r5

同時に生存する仮想レジスタには、異なる物理レジスタを割り当てます。 生存期間が重ならない仮想レジスタは、同じ物理レジスタを共有できます。

線形走査レジスタ割当て

基本実装では、線形走査によるレジスタ割当てを使用します。

  1. 各仮想レジスタの生存区間を求める
  2. 生存区間を開始位置の順に並べる
  3. 終了した生存区間を割当て中の集合から取り除く
  4. 空いている物理レジスタを現在の生存区間へ割り当てる
  5. 空きがない場合は、いずれかの値をspillする

終了位置が遠い値をspill候補にすると、 近くで使用される値を物理レジスタへ残しやすくなります。

関数呼出しと生存値

関数呼出しは、caller-saveレジスタの内容を変更する可能性があります。 呼出し後にも必要な値は、呼出しをまたいで生存しています。 

add  v3, v1, v2
call v4, f(v5)
mul  v6, v3, v4

v3は関数呼出し後にも使用されます。 v3をcaller-saveレジスタへ割り当てる場合は、 呼出し前に保存し、呼出し後に復元しなければなりません。

基本実装では、呼出しをまたいで生存する値を callee-saveレジスタへ優先的に割り当てます。 割り当てられない場合はスタックへ退避します。

spill

利用可能な物理レジスタに収まらない値は、 関数のスタックフレーム内にあるspill slotへ配置します。 

v2 -> spill slot 0
v7 -> spill slot 1

spillされた値を使用する命令の前にはloadを挿入し、 spillされた値を定義する命令の後にはstoreを挿入します。

spillされた値の読み出し

次の命令で、v2がspillされているとします。

add v3, v1, v2

一時レジスタへ値を読み出してから演算します。

load temporary, spill_slot_0
add  r5, r6, temporary

spillされた値への書き込み

次の命令で、結果のv3がspillされているとします。

add v3, v1, v2

一時レジスタで計算し、結果をスタックへ書き込みます。

add   temporary, r5, r6
store temporary, spill_slot_0

一時レジスタ

spillとreloadのために必要な一時レジスタは、 通常のレジスタ割当てから除外して予約します。

基本実装では、r8とr9を spill処理用の一時レジスタとして予約しても構いません。 その場合、通常の値へ割り当てるcaller-saveレジスタは r5からr7までになります。

物理レジスタ中間表現

レジスタ割当てとspill命令の挿入が終わると、 仮想レジスタはすべて物理レジスタまたはスタックスロットへ置き換えられます。

r ::= 物理レジスタ
r0 | r1 | ... | r15 仮想CPUのレジスタ

物理レジスタ中間表現は、仮想レジスタ中間表現と同じく、 関数と基本ブロックの集合として表します。

通常命令と終端命令の構造も同じですが、 オペランドには物理レジスタを使用します。 spill slotのオフセットは、次のスタックフレーム配置で確定します。

呼出し規約への変換

仮想レジスタ中間表現の関数呼出しを、 仮想CPUの呼出し規約に従う命令列へ変換します。 

call v_result, f(v1, v2, v3)

例えば、次のように変換します。

mov  r1, register_of(v1)
mov  r2, register_of(v2)
mov  r3, register_of(v3)
call f
mov  register_of(v_result), r1

第5引数以降は、呼出し規約に従ってスタックへ配置します。

クロージャ呼出し

クロージャ呼出しでは、クロージャポインタをr13へ配置します。 

mov   r13, closure_register
load  temporary, 0(r13)
callr temporary

caller-saveレジスタ

呼出し後にも必要なcaller-saveレジスタの値は、 呼出し前にスタックへ保存し、呼出し後に復元します。 

store r5, caller_save_slot(r14)
call  f
load  r5, caller_save_slot(r14)

callee-saveレジスタ

関数内で使用するcallee-saveレジスタは、 関数入口で保存し、すべての通常の関数出口で復元します。

並列コピー

関数の引数をレジスタへ配置するときは、 複数のコピーを同時に行う並列コピーとして扱います。

例えば、次の引数配置を考えます。

r1 <- r2
r2 <- r1

単純に上から実行すると元のr1が失われます。 そのため、一時レジスタを使用します。 

mov temporary, r1
mov r1, r2
mov r2, temporary

コピー関係に循環がなければ、元の値を上書きしない順序でコピーします。 循環がある場合だけ一時レジスタまたは一時スタックスロットを使用します。

スタックフレーム配置

各関数について、保存領域、spill領域、呼出し用領域の位置を決定します。

領域 内容
保存領域 戻りアドレスと使用するcallee-saveレジスタ
spill領域 物理レジスタへ割り当てられなかった値
caller-save領域 関数呼出しをまたいで保持するcaller-saveレジスタ
引数領域 第5引数以降の受渡しに使用する領域
GC情報 発展　ヒープポインタを保持するスタックスロット

スタックフレームの大きさは、必要な全領域のワード数から決定します。 

frame_size =
    saved_register_count
    + spill_slot_count
    + caller_save_slot_count
    + outgoing_argument_count

スタックスロットの配置

抽象的なスタックスロットへ、r14からのオフセットを割り当てます。

saved r15    -> 5(r14)
saved r10    -> 4(r14)
spill slot 0 -> 3(r14)
spill slot 1 -> 2(r14)
caller slot  -> 1(r14)
argument 5   -> 0(r14)

関数入口

関数入口では、スタックフレームを確保し、 戻りアドレスと使用するcallee-saveレジスタを保存します。 

function_label:
    addi  r14, r14, -frame_size
    store r15, saved_r15_offset(r14)
    store r10, saved_r10_offset(r14)
    store r11, saved_r11_offset(r14)

使用しないcallee-saveレジスタは保存しません。

関数出口

関数出口では、戻り値をr1へ配置し、 保存したレジスタを復元してスタックフレームを破棄します。 

mov   r1, result_register
load  r11, saved_r11_offset(r14)
load  r10, saved_r10_offset(r14)
load  r15, saved_r15_offset(r14)
addi  r14, r14, frame_size
ret

関数内に複数のreturnがある場合は、 共通の関数出口ブロックへジャンプさせることができます。

末尾呼出し

末尾呼出しでは、現在の関数へ戻る必要がないため、 新しい戻りアドレスとスタックフレームを作りません。

  1. 呼出し先の引数を求める
  2. 引数を呼出し規約で定めた位置へ並列コピーする
  3. 保存したcallee-saveレジスタと戻りアドレスを復元する
  4. 現在のスタックフレームを破棄する
  5. 呼出し先へジャンプする
; 引数を配置する
mov  r1, next_argument_1
mov  r2, next_argument_2

; 保存した値を復元する
load r10, saved_r10_offset(r14)
load r15, saved_r15_offset(r14)

; フレームを破棄する
addi r14, r14, frame_size

; 呼出し先へ移動する
jump next_function

間接末尾呼出し

クロージャへの末尾呼出しでは、 クロージャポインタをr13へ配置し、 コードアドレスへ間接ジャンプします。 

mov   r13, closure_register
load  temporary, 0(r13)
addi  r14, r14, frame_size
jumpr temporary

線形化

物理レジスタ中間表現の基本ブロックを、 ラベルとジャンプを持つ一列の命令列へ並べます。

次の基本ブロックを考えます。

entry:
    branch r5, then_block, else_block

then_block:
    add r6, r1, r2
    jump end_block

else_block:
    sub r6, r1, r2
    jump end_block

end_block:
    return r6

線形化後は、例えば次のようになります。

entry:
    brz r5, else_block

then_block:
    add  r6, r1, r2
    jump end_block

else_block:
    sub  r6, r1, r2

end_block:
    mov  r1, r6
    jump function_exit

次に実行するブロックを命令列上の直後へ配置できる場合は、 不要なジャンプを削除します。

ブロックの配置順序

基本実装では、関数の入口ブロックから深さ優先で基本ブロックを並べます。 まだ配置されていない後続ブロックを、可能な限り直後へ配置します。

到達不能な基本ブロックは、線形化前に削除できます。

switchの出力

仮想CPUに多方向分岐命令を直接持たせない場合、 switchを比較と条件分岐の列へ変換します。 

switch r5 [
    0: case_0,
    1: case_1,
    2: case_2
]

分岐数が少ない場合は、次のように変換できます。

li   temporary, 0
seq  temporary, r5, temporary
brnz temporary, case_0

li   temporary, 1
seq  temporary, r5, temporary
brnz temporary, case_1

jump case_2

発展仕様では、分岐数が多く値が連続している場合に ジャンプテーブルを使用できます。

アセンブリ出力

線形化された物理レジスタ命令を、 仮想CPUのアセンブリ文法に従って出力します。

主に次の内容を出力します。

  • .textセクション
  • 関数ラベルと命令列
  • .dataセクション
  • 文字列、浮動小数点数、定数ブロック
  • .globalと.extern
  • .entryによるエントリポイント
.text
.global main
.entry main

main:
    addi  r14, r14, -2
    store r15, 1(r14)

    li    r1, 85
    call  runtime_print_int

    li    r1, 1
    load  r15, 1(r14)
    addi  r14, r14, 2
    ret

静的データの出力

低水準中間表現から保持されている静的データを、 .dataセクションへ出力します。 

.data

string_0:
    .string "hello"

float_0:
    .word 0x40091eb851eb851f

静的ブロックには、ヘッダとフィールドを順番に出力します。 関数や静的データへの参照はラベルとして出力し、 アセンブラまたはリンカがアドレスを解決します。

物理レジスタ中間表現の検査

アセンブリ出力の前に、少なくとも次の条件を検査します。

  • すべての仮想レジスタが除去されていること
  • 使用される物理レジスタがr0からr15の範囲内であること
  • r0への有効な書き込みを期待していないこと
  • r13、r14、r15の予約用途が守られていること
  • すべてのspill slotに具体的なオフセットがあること
  • すべての基本ブロックが終端命令を持つこと
  • すべての分岐先ラベルが同じ関数内に存在すること
  • 関数呼出しの引数数が呼出し規約に従っていること
  • 通常の関数出口でスタックポインタが復元されること

コード生成の結果

  • すべての仮想レジスタが物理レジスタまたはスタックスロットへ配置される
  • spillされた値に対するloadとstoreが挿入される
  • 関数呼出しが呼出し規約に従う命令列へ変換される
  • 関数ごとのスタックフレームが決定される
  • 末尾呼出しがフレームを増やさないジャンプへ変換される
  • 基本ブロックがラベル付き命令列へ線形化される
  • 静的データとコードがアセンブリとして出力される

出力されたアセンブリはアセンブラによって実行可能命令列へ変換され、 仮想CPUによって実行されます。
