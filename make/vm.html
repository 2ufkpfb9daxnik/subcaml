仮想マシン仕様

仮想マシンは、アセンブラが生成した実行可能形式を読み込み、 命令配列、レジスタ、メモリ、プログラムカウンタを使用して プログラムを実行します。

このページでは、実行時の値表現、呼出し規約、仮想CPUの状態、 基本命令の意味、実行可能形式の読込み、ランタイムAPIを定義します。 アセンブリの文法、疑似命令の展開、ラベル解決、 実行可能形式の生成方法は assembly.htmlで定義します。

仕様の構成

項目 内容
値表現 64ビットワード、タグ付き即値、ヒープブロック
呼出し規約 引数、戻り値、保存レジスタ、クロージャ、スタックフレーム
仮想CPUの状態 命令配列、レジスタ、メモリ、プログラムカウンタ、停止状態
命令の意味 各基本命令がCPU状態をどのように更新するか
実行可能形式の読込み 命令列と静的データの配置、初期状態の構築
ランタイムAPI 入出力、メモリ確保、文字列、比較などの実行時処理

ワード

仮想CPUのレジスタとメモリは、64ビットの値を扱います。 この64ビット値を1ワードと呼びます。

項目 仕様
ワード幅 64ビット
算術演算 2の補数による符号付き64ビット整数演算
メモリアドレス ワード単位の非負整数
メモリオフセット ワード単位の符号付き整数
コードアドレス 命令配列内の位置

実行時の値

通常の言語値は、タグ付き即値またはブロックへのポインタとして 1ワードに格納します。

値の分類 低水準表現 主な値
タグ付き整数 最下位ビットが1のワード int、char
定数値 タグ付き整数と同じ即値表現 bool、unit、 引数を持たないコンストラクタ
ブロックポインタ 最下位ビットが0の有効なメモリアドレス タプル、レコード、リスト、参照、文字列、クロージャ、 引数を持つコンストラクタ
セルフホスト後配列ポインタ 可変長ヒープブロックへのポインタ 配列
セルフホスト後浮動小数点値 IEEE 754 binary64を格納した専用ブロックへのポインタ float

タグ付き整数

ソース言語の整数 nは、次の式でタグ付き整数へ変換します。 

tag_int(n) = (n << 1) | 1
untag_int(w) = w >> 1

untag_intでは算術右シフトを使用します。 表現可能な通常の整数は -2^62以上 2^62 - 1以下です。

ソース値 内部表現
0 1
1 3
2 5
-1 -1
false 1
true 3
() 1

静的型検査が完了しているため、 整数0、偽、単位値が同じビット表現を使用しても、 型の異なる操作へ混同されることはありません。

文字

文字は、Unicodeコードポイントを格納したタグ付き整数として表します。 有効な文字値はUnicodeスカラー値の範囲に限ります。

操作 規則
文字からコードポイント タグ付き整数として格納された値を使用する
コードポイントから文字 Unicodeスカラー値であることを検査する
文字の比較 コードポイントのタグ付き整数を比較する

ヒープブロック

複合値は、1ワードのヘッダと0個以上のフィールドからなる ブロックとして表します。 値として使用するポインタはフィールド0を指し、 ヘッダはオフセット -1に置きます。 

+--------+---------+---------+-----+
| header | field 0 | field 1 | ... |
+--------+---------+---------+-----+
             ^
             |
        値として使うポインタ
位置 内容
オフセット-1 ブロックヘッダ
オフセット0 フィールド0
オフセットi フィールドi

ブロックヘッダ

ブロックヘッダは、少なくともブロックタグとフィールド数を保持します。 正確なビット配置は実装時に一つへ固定します。

情報 用途
タグ コンストラクタ番号またはブロックの種類を識別する
サイズ フィールド数を表す
セルフホスト後GC情報 世代、色、マーク状態などを保持する

基本配置では、下位8ビットをタグ、 上位ビットをフィールド数として使用できます。 

make_header(tag, size) =
    (size << 8) | tag

header_tag(header) =
    header & 0xff

header_size(header) =
    header >> 8

ブロックの種類

値 タグ フィールド
タプル tuple_tag 各要素
レコード record_tag 宣言順に並べた各フィールド
引数を持つコンストラクタ コンストラクタ固有のタグ コンストラクタの各引数
consセル cons_tag フィールド0に先頭要素、フィールド1に残りのリスト
参照セル reference_tag フィールド0に現在の値
クロージャ closure_tag フィールド0にコードアドレス、フィールド1以降に自由変数
文字列 string_tag バイト長とUTF-8データ
セルフホスト後配列 array_tag 各要素。ヘッダのサイズ欄を配列長として使用する
セルフホスト後浮動小数点数 float_tag IEEE 754 binary64のビット列

文字列ブロック

文字列はUTF-8で格納します。 文字列の長さには、バイト長と文字数の二種類があるため、 ランタイムAPIの各操作がどちらを返すかを区別します。

位置 内容
ヘッダ 文字列タグとデータ部分のワード数
フィールド0 UTF-8バイト長を表すタグ付き整数
フィールド1以降 UTF-8バイト列をワード単位で格納したデータ
未使用バイト 最後のワードの残りを0で埋める

runtime_string_lengthは文字数を返します。 文字列内部のバイト長は、UTF-8走査と境界検査に使用します。

コードアドレスは命令配列内の位置を表します。 クロージャ呼出しでは、 クロージャポインタを r13へ設定してから、 フィールド0のコードアドレスを使用して間接呼出しを行います。

静的ブロック

コンパイル時に内容が確定する文字列や定数ブロックは、 実行開始前に静的データ領域へ配置します。 静的ブロックもヒープブロックと同じヘッダ配置を使用します。

性質 規則
アドレス VMのロード時に静的データ領域内のメモリアドレスへ変換する
参照方法 通常のブロックポインタと同じ方法で参照する
書込み 基本仕様では静的ブロックへの書込みを実行時エラーとする
寿命 プログラムの実行開始から終了まで存在する

呼出し規約

関数の引数、戻り値、クロージャ環境、戻り先、 保存レジスタは次の規約に従って受け渡します。

レジスタの用途

レジスタ 用途 保存規則
r0 常に0を保持する 書込みは破棄される
r1からr4 第1引数から第4引数 caller-save
r1 戻り値 呼出しによって必ず変更され得る
r5からr9 汎用レジスタ caller-save
r10からr12 汎用レジスタ callee-save
r13 クロージャ環境ポインタ caller-save
r14 スタックポインタ 関数復帰時に呼出し前の値へ戻す
r15 戻りアドレス 非leaf関数は必要に応じて保存する

引数と戻り値

値 受渡し位置
第1引数 r1
第2引数 r2
第3引数 r3
第4引数 r4
第5引数以降 呼出し元が用意したスタック引数領域
戻り値 r1
クロージャ環境 r13

unitを返す関数も、 r1へ単位値 1を格納します。

スタック引数

第5引数以降は、呼出し元のフレーム内に確保した outgoing argument領域へ格納します。 呼出し直前の r14を基準として、次の位置を使用します。

引数 位置
第5引数 0(r14)
第6引数 1(r14)
第n引数 n - 5(r14)

呼出された関数が自身のスタックフレームを確保した後は、 呼出し元の引数領域が frame_sizeワード高い位置に移動します。 コンパイラは、関数入口で必要な引数を割当て先へ読み込みます。

直接呼出し

mov  r1, argument1
mov  r2, argument2
call function_label

callは jal r15, function_labelの疑似命令です。 次の命令位置を r15へ保存して呼出し先へ移動します。

クロージャ呼出し

mov   r13, closure
load  r5, 0(r13)
mov   r1, argument1
callr r5

呼出された関数は、 r13のフィールド1以降から自由変数を読み出します。

レジスタの保存

分類 対象 保存する側
caller-save r1からr9、 r13、r15 呼出し後にも値が必要な場合に呼出し側が保存する
callee-save r10からr12 使用する場合に呼出される側が保存して復元する
スタックポインタ r14 呼出された関数が復帰前に元の値へ戻す

スタックフレーム

スタックは高位アドレスから低位アドレスへ伸びます。 関数は入口で r14を減らしてフレームを確保します。 

高位アドレス
+----------------------------+
| 呼出し元のフレーム         |
+----------------------------+
| 第5引数以降                |
+----------------------------+
| 保存した戻りアドレス       |
+----------------------------+
| 保存したcallee-save値      |
+----------------------------+
| spill領域                  |
+----------------------------+
| caller-save保存領域        |
+----------------------------+
| outgoing argument領域      |
+----------------------------+  <- r14
低位アドレス

関数入口

function_label:
    addi  r14, r14, -frame_size
    store r15, saved_r15_offset(r14)
    store r10, saved_r10_offset(r14)
    store r11, saved_r11_offset(r14)

使用しないcallee-saveレジスタは保存しません。 呼出しを行わないleaf関数では、 戻りアドレスとスタックフレームの保存を省略できる場合があります。

関数出口

function_exit:
    load  r11, saved_r11_offset(r14)
    load  r10, saved_r10_offset(r14)
    load  r15, saved_r15_offset(r14)
    addi  r14, r14, frame_size
    ret

戻り値は、関数出口へ移動する前に r1へ配置します。

末尾呼出し

末尾呼出しでは、新しい戻りアドレスを作りません。 呼出し先の引数を安全な位置へ配置し、 現在のフレームを破棄してから呼出し先へジャンプします。

処理順序 処理
1 呼出し先の引数値とコードアドレスを求める
2 フレーム破棄で失われる値を一時位置へ保存する
3 callee-saveレジスタとr15を復元する
4 現在のスタックフレームを破棄する
5 引数を規定のレジスタとスタック位置へ配置する
6 jumpまたはjumprで呼出し先へ移動する

部分適用

部分適用は仮想CPUの機能ではありません。 コンパイラが生成した補助関数とクロージャ、 またはランタイム関数によって実装します。 仮想CPUは通常のクロージャ呼出しとして実行します。

仮想CPUの状態

仮想CPUの状態を Sとし、 次の要素から構成します。

状態 内容
code ラベル解決済みの基本命令配列
registers r0からr15までの64ビットレジスタ
memory 静的データ、ヒープ、スタックを格納するワード配列
pc 次に実行する命令配列内の位置
heap_next 次のヒープ確保で使用するメモリアドレス
static_end 静的データ領域の直後のアドレス
halted 仮想CPUが停止しているかを表す真偽値
exit_code プログラムの終了コード
error 実行時エラーが発生した場合の詳細

レジスタの規則

操作 規則
read_register(0) 常に0を返す
write_register(0, value) 書込みを破棄する
read_register(i) 1以上15以下ならregisters[i]を返す

範囲外の番号 実行可能形式の検査エラーとする

| スタック                   |

静的データ ロード時に低位アドレスから配置する 基本仕様では読取り専用
ヒープ 低位アドレスから高位アドレスへ成長する 許可する
スタック 高位アドレスから低位アドレスへ成長する 許可する

ヒープ確保

基本仕様では、ヒープ確保はbump allocationで実装します。 要求されたワード数だけ heap_nextを進めます。 

allocate(size):
    if size < 0:
        runtime error

    base = heap_next
    next = heap_next + size

    if next > r14:
        out of memory

    heap_next = next
    return base

ヒープとスタックが衝突する場合は、 基本仕様ではメモリ不足として停止します。

セルフホスト後ガベージコレクション

ガベージコレクションを導入する場合は、 メモリ不足を報告する前に runtime_gcを実行します。 GCはレジスタ、スタック、静的データ、大域値から 到達可能なヒープブロックを追跡します。

ルート 追跡方法
レジスタ GCマップまたは値タグでポインタを判定する
スタックスロット GCマップまたは値タグでポインタを判定する
静的データ 静的ブロック内のポインタフィールドを走査する
大域値 大域値領域に格納された値を走査する

実行可能形式

仮想CPUはアセンブラが生成した実行可能形式を受け取ります。 アセンブリテキストの解析やラベル解決は行いません。

フィールド 内容

entry 最初に実行する命令の位置 
type executable = {
    code : instruction array;
    data : int64 array;
    data_relocations : relocation array;
    entry : int;

命令実行ループ

while not state.halted do
    if state.pc is outside state.code then
        runtime_error invalid_program_counter

通常の命令は、命令の効果を適用した後に pcを1増やします。 ジャンプ、分岐、関数呼出し、復帰は 命令自身が次の pcを設定します。

基本命令

次の命令だけを仮想CPUが直接実行します。 call、 callr、 ret、 neg、 subiなどの疑似命令は、 アセンブラによって基本命令へ展開済みです。

定数と転送

命令 状態更新 次のpc
li rd, i registers[rd] = i pc + 1
la_code rd, p registers[rd] = p pc + 1
la_data rd, a registers[rd] = a pc + 1
mov rd, rs registers[rd] = registers[rs] pc + 1

アセンブリ上の laは、ラベルの種類に応じて la_codeまたは la_dataに解決されます。

算術命令

命令 状態更新 エラー条件
add rd, rs1, rs2 rd = rs1 + rs2 なし。64ビットでラップアラウンドする
sub rd, rs1, rs2 rd = rs1 - rs2 なし。64ビットでラップアラウンドする
mul rd, rs1, rs2 rd = rs1 * rs2 なし。下位64ビットを保持する
div rd, rs1, rs2 rd = signed_div(rs1, rs2) 除数が0、または最小値を-1で除算した場合
rem rd, rs1, rs2 rd = signed_rem(rs1, rs2) 除数が0
addi rd, rs, i rd = rs + i なし。64ビットでラップアラウンドする

算術命令は生の64ビット整数を処理します。 タグ付き整数のタグ補正は生成コードが明示的に行います。

ビット命令

命令 状態更新
and rd, rs1, rs2 rd = rs1 & rs2
or rd, rs1, rs2 rd = rs1 | rs2
xor rd, rs1, rs2 rd = rs1 ^ rs2
not rd, rs rd = bitwise_not(rs)
shl rd, rs1, rs2 rd = rs1 << (rs2 & 63)
shr rd, rs1, rs2 rd = logical_shift_right(rs1, rs2 & 63)
sar rd, rs1, rs2 rd = arithmetic_shift_right(rs1, rs2 & 63)

比較命令

命令 状態更新
seq rd, rs1, rs2 値が等しければ rd = 1、 それ以外なら rd = 0
slt rd, rs1, rs2 符号付き比較で rs1 < rs2なら rd = 1、 それ以外なら rd = 0

比較命令の結果は生の0または1です。 ソース言語の真偽値として使用する場合は、 生成コードが tag_intを適用します。

メモリ命令

命令 実効アドレス 状態更新
load rd, o(rs) registers[rs] + o 検査後、対象ワードをrdへ格納する
store rs, o(rd) registers[rd] + o 検査後、rsの値を対象ワードへ格納する

実効アドレスの計算で64ビット範囲を超えた場合、 メモリ範囲外の場合、書込み禁止領域の場合は実行時エラーとします。

ジャンプと分岐

命令 条件 次のpc
jump p なし p
jumpr rs なし registers[rs]
brz rs, p registers[rs] = 0 成立時はp、不成立時はpc + 1
brnz rs, p registers[rs] != 0 成立時はp、不成立時はpc + 1

移動先は命令配列の範囲内でなければなりません。 間接ジャンプでは、レジスタの値をコードアドレスとして検査します。

関数呼出し命令

命令 リンク値 次のpc
jal rd, p registers[rd] = pc + 1 p
jalr rd, rs registers[rd] = pc + 1 命令実行前のregisters[rs]

jalrでは、リンク値を書き込む前に 移動先アドレスを読み取ります。 そのため rdと rsが同じ場合でも正しく実行できます。

trap 7 実行時エラーの報告 r1のエラー番号または値 停止する

ランタイムAPI

ランタイムAPIは、生成コードから通常の呼出し規約で利用する関数です。 引数は r1から順に渡し、 戻り値は r1で返します。

ホスト環境の処理が必要なランタイム関数は、 内部で trapを使用します。 コンパイラは原則として trapを直接生成せず、 ランタイム関数を呼び出します。

停止

停止方法 終了状態
halt halted = true。 終了コードは現在の exit_code
trap 0 r1を終了コードとして保存し、 halted = true
実行時エラー errorを設定し、 非正常終了コードで停止する

仮想マシンの検査条件

  • r0の読出し結果が常に0である
  • r0への書込みがCPU状態へ影響しない
  • pcが停止時を除いて命令配列の範囲内にある
  • r14がメモリ範囲内のスタック位置を表している
  • heap_nextが静的データ領域の終端以上である
  • heap_nextがr14を超えていない
  • 静的データ領域への書込みが発生していない
  • 直接ジャンプ先と直接呼出し先が有効なコード位置である
  • 間接ジャンプ先と間接呼出し先が有効なコードアドレスである
  • メモリアクセスの実効アドレスが有効な割当て済み領域にある
  • ランタイムAPIが呼出し規約に従って引数と戻り値を扱う
  • セルフホスト後配列操作が配列ブロックだけを対象にする
  • セルフホスト後GC後もすべての生存ポインタが有効なブロックを指す

実装後に成立する条件

  • 実行可能形式を検査してから実行を開始する
  • 静的データがヒープより前のメモリ領域へ配置される
  • データアドレスの再配置がロード時に適用される
  • コードアドレスが命令配列内の位置として扱われる
  • 通常命令の実行後にpcが1増える
  • 制御移動命令が指定したコード位置へpcを変更する
  • 関数呼出しが次の命令位置をリンクレジスタへ保存する
  • メモリアクセスがワード単位のアドレスとオフセットを使用する
  • ヒープが低位側から高位側へ成長する
  • スタックが高位側から低位側へ成長する
  • ヒープとスタックの衝突が実行時エラーになる
  • ランタイム処理が通常の呼出し規約またはtrap規約に従う
  • 停止後に追加の命令を実行しない
