仮想マシンなどの仕様

値表現

仮想CPUのレジスタとメモリは、64ビットの値を扱います。 この64ビットの値を1ワードと呼びます。

v ::= 値
タグ付き整数 int
定数値 bool、unit、引数を持たないコンストラクタ
ヒープポインタ ヒープ上のブロックを指す値

整数

整数nは、最下位ビットをタグとして使用し、 次のように表現します。 

(n << 1) | 1
整数 内部表現
0 1
1 3
2 5
-1 -1

最下位ビットが1なら即値、 0ならヒープポインタとして扱います。

真偽値と単位値

値 内部表現
false 整数0と同じ表現
true 整数1と同じ表現
() 整数0と同じ表現

文字

文字は、その文字コードをタグ付き整数として表現します。

ヒープブロック

組、レコード、ヴァリアント、リスト、文字列、クロージャ、 参照、配列は、ヒープ上のブロックとして表現します。 レジスタにはブロックそのものではなく、その先頭を指すポインタを格納します。 

+--------+---------+---------+-----+
        | header | field 0 | field 1 | ... |
        +--------+---------+---------+-----+
                    ^
                    |
                ポインタ

ヘッダには、ブロックのフィールド数と種類を表すタグを格納します。

ブロック 主なフィールド
組 各要素
レコード 各フィールド
ヴァリアント コンストラクタのタグと引数
リスト 先頭要素と残りのリスト
クロージャ コードアドレスと自由変数
参照 現在格納されている値
文字列 長さと文字データ
配列 発展　長さと各要素

浮動小数点数

浮動小数点数は、基本仕様ではヒープ上にボックス化して格納します。 ヒープブロックには64ビット浮動小数点数のビット列を保存します。

静的な値

文字列リテラルやコンパイル時に決定できる定数ブロックは、 実行開始前に静的データ領域へ配置します。 プログラム中では、通常のヒープブロックと同様にポインタで参照します。

呼出し規約

関数の引数、戻り値、クロージャ、戻り先は、以下の規約に従って受け渡します。

レジスタの用途

レジスタ 用途
r0 常に0
r1～r4 関数の引数
r1 戻り値
r5～r9 呼出し側が保存する汎用レジスタ
r10～r12 呼出される側が保存する汎用レジスタ
r13 クロージャポインタ
r14 スタックポインタ
r15 戻りアドレス

引数と戻り値

第1引数から第4引数までは、r1からr4へ順番に格納します。 第5引数以降はスタックへ格納します。 

f x1 x2 x3 x4 x5

            r1 = x1
            r2 = x2
            r3 = x3
            r4 = x4
            stack[0] = x5

関数の戻り値はr1へ格納します。 unitを返す関数も、r1へ単位値を格納します。

レジスタの保存

r1からr9、r13、r15は、 関数呼出しによって書き換えられる可能性があります。 呼出し後にも必要な値は、呼出し側が事前に保存します。

r10からr12は、呼出された関数が元の値を保存します。 これらのレジスタを使用する関数は、関数入口で値を保存し、 関数出口で復元します。

直接呼出し

呼出す関数がコンパイル時に分かっている場合は、関数ラベルを直接指定します。 

mov  r1, argument1
            mov  r2, argument2
            call function_label

callは次の命令に戻るためのアドレスをr15へ保存し、 指定された関数へ移動します。

クロージャ呼出し

関数値をクロージャとして呼び出す場合は、 クロージャポインタをr13へ格納します。 

mov   r13, closure
            load  r5, code_offset(r13)
            mov   r1, argument1
            callr r5

呼出された関数は、r13を通して自由変数を読み出します。 

load r5, free_variable_offset(r13)

スタックフレーム

各関数は、必要に応じてスタック上にフレームを確保します。 スタックは大きいアドレスから小さいアドレスへ伸びます。

スタックフレームには、主に次の値を置きます。

  • 保存した戻りアドレス
  • 保存したレジスタ
  • レジスタに収まらなかった値
  • 第5引数以降の関数引数
高位アドレス
            +--------------------+
            | 第5引数以降        |
            +--------------------+
            | 戻りアドレス       |
            +--------------------+
            | 保存レジスタ       |
            +--------------------+
            | spill領域          |
            +--------------------+  <- r14
            低位アドレス

関数入口と関数出口

関数入口では、必要な大きさだけスタックポインタを移動し、 保存が必要なレジスタをスタックへ退避します。 

function_label:
                addi  r14, r14, -4
                store r15, 3(r14)
                store r10, 2(r14)
                store r11, 1(r14)
                store r12, 0(r14)

関数出口では、保存した値を復元し、スタックポインタを元へ戻してから 呼出し元へ戻ります。 

    load  r12, 0(r14)
                load  r11, 1(r14)
                load  r10, 2(r14)
                load  r15, 3(r14)
                addi  r14, r14, 4
                ret

末尾呼出し

関数の最後に別の関数を呼び出す場合は、新しい戻り先を保存しません。 現在のスタックフレームを破棄し、引数を配置してから呼出し先へジャンプします。 

mov   r1, next_argument1
            mov   r2, next_argument2
            addi  r14, r14, frame_size
            jump  next_function

クロージャへの末尾呼出しでは、クロージャポインタをr13へ設定し、 クロージャから読み出したコードアドレスへ間接ジャンプします。

部分適用

関数へ必要な数より少ない引数を渡した場合は、 与えられた引数を保存した新しいクロージャを返します。 この処理は仮想CPUではなく、コンパイラが生成する補助関数またはランタイムが行います。

必要な数より多い引数を渡した場合は、最初の呼出し結果として得られた関数へ、 残りの引数を続けて適用します。

仮想CPUの状態

仮想CPUは、命令列、静的データ、レジスタ、メモリ、 プログラムカウンタ、停止状態を持ちます。

code 実行する命令列
data 文字列や定数ブロックを格納する静的データ
registers r0からr15までのレジスタ
memory ヒープとスタックを格納するメモリ
pc 次に実行する命令の位置
halted 仮想CPUが停止しているかを表す値

レジスタ

仮想CPUは、64ビット幅のレジスタを16本持ちます。 r0の値は常に0です。 r0への書き込みは破棄されます。 

registers[0]  = r0
        registers[1]  = r1
        ...
        registers[15] = r15

プログラムカウンタ

プログラムカウンタpcは、 次に実行する命令の配列番号を表します。

通常の命令を実行した後は、pcを1増やします。 ジャンプ、分岐、関数呼出し、復帰では、 命令が指定する位置へpcを変更します。

メモリ

メモリは64ビットワードの配列です。 メモリアドレスはワード単位で表します。 

memory[0]
        memory[1]
        memory[2]
        ...

メモリの低位側をヒープ、高位側をスタックとして使用します。 ヒープは低位側から高位側へ、スタックは高位側から低位側へ伸びます。 

低位アドレス
        +--------------------+
        | 静的データ         |
        +--------------------+
        | ヒープ             |
        |        ↓           |
        |                    |
        |        ↑           |
        | スタック           |
        +--------------------+
        高位アドレス

ヒープとスタックが衝突した場合は、メモリ不足として実行を停止します。

初期状態

プログラムを開始するとき、仮想CPUを次のように初期化します。

pc 実行可能形式で指定されたエントリポイント
r0～r13 0
r14 スタック領域の終端アドレス
r15 0
halted false

命令の実行

仮想CPUは、停止するまで次の処理を繰り返します。

  1. code[pc]から命令を取得する
  2. 命令に従ってレジスタ、メモリ、pcを更新する
  3. haltedがtrueでなければ次の命令を実行する

停止

halt命令を実行すると、 haltedをtrueにして実行を終了します。

実行時エラーが発生した場合も仮想CPUを停止し、 エラーの種類、命令位置、実行中の命令を報告します。

仮想命令セット

仮想CPUは16本の汎用レジスタ、プログラムカウンタ、メモリを持ちます。 各命令は、特に記載がない限り実行後に次の命令へ進みます。

オペランド

r レジスタ
i 整数即値
o メモリオフセット
L コードまたは静的データのラベル
n ランタイム処理の番号

定数と転送

li rd, i 即値をrdへ格納する
la rd, L ラベルのアドレスをrdへ格納する
mov rd, rs rsの値をrdへコピーする

整数演算

add rd, rs1, rs2 加算
sub rd, rs1, rs2 減算
mul rd, rs1, rs2 乗算
div rd, rs1, rs2 除算
rem rd, rs1, rs2 剰余
addi rd, rs, i 即値加算

これらの命令は、生の64ビット整数を演算します。 タグ付き整数のタグ付けとタグ解除は、コンパイラがビット演算を使って行います。

ビット演算

and rd, rs1, rs2 ビット論理積
or rd, rs1, rs2 ビット論理和
xor rd, rs1, rs2 ビット排他的論理和
not rd, rs ビット反転
shl rd, rs1, rs2 左シフト
shr rd, rs1, rs2 論理右シフト
sar rd, rs1, rs2 算術右シフト

比較

seq rd, rs1, rs2 等しければ1、それ以外なら0を格納する
slt rd, rs1, rs2 rs1 < rs2なら1、それ以外なら0を格納する

sne、sle、sgt、 sgeは、アセンブラが基本命令へ展開する疑似命令とします。

メモリアクセス

load rd, o(rs) rs + o番地の1ワードをrdへ読み出す
store rs, o(rd) rsの1ワードをrd + o番地へ書き込む

メモリアドレスとオフセットはワード単位とします。 不正なアドレスへのアクセスは実行時エラーになります。

ジャンプと分岐

jump L ラベルLへ移動する
jumpr rs rsが示す命令位置へ移動する
brz rs, L rsが0ならラベルLへ移動する
brnz rs, L rsが0でなければラベルLへ移動する

関数呼出し

jal rd, L 次の命令位置をrdへ保存し、ラベルLへ移動する
jalr rd, rs 次の命令位置をrdへ保存し、rsが示す命令位置へ移動する

次の表記は疑似命令とします。

call L jal r15, L
callr rs jalr r15, rs
ret jalr r0, r15

ランタイム呼出しと停止

trap n 番号nのランタイム処理を呼び出す
halt 仮想CPUを停止する

入出力、ヒープ確保、文字列操作、構造的比較などは、 通常の関数またはtrapを通してランタイムが処理します。

疑似命令

nop 何も行わない
neg rd, rs 符号反転
subi rd, rs, i 即値減算
push rs スタックへ1ワード保存する
pop rd スタックから1ワード読み出す

疑似命令は仮想CPUが直接実行しません。 アセンブラが一つ以上の基本命令へ展開します。

浮動小数点演算

基本仕様では浮動小数点数をヒープ上にボックス化するため、 浮動小数点演算はランタイム関数として実装します。 

runtime_float_add
        runtime_float_sub
        runtime_float_mul
        runtime_float_div

発展仕様では、浮動小数点レジスタと次の命令を追加できます。

fadd fd, fs1, fs2 発展　浮動小数点加算
fsub fd, fs1, fs2 発展　浮動小数点減算
fmul fd, fs1, fs2 発展　浮動小数点乗算
fdiv fd, fs1, fs2 発展　浮動小数点除算

実行時エラー

仮想CPUは、少なくとも次の場合に実行時エラーを報告します。

  • ゼロによる除算または剰余
  • メモリ範囲外へのアクセス
  • 存在しない命令位置へのジャンプ
  • 未知のtrap番号の呼出し
  • スタックとヒープの衝突

アセンブリ文法

アセンブリプログラムは、命令、ラベル、ディレクティブ、コメントから構成されます。 空行と改行は、命令の区切りとして使用できます。

字句要素

x 識別子
L ラベル
r レジスタ
i 整数即値
s 文字列リテラル

プログラム

P ::= アセンブリプログラム
u1 ... un アセンブリ項目の列

アセンブリ項目

u ::= アセンブリ項目
I 命令
L: ラベル定義
D ディレクティブ

レジスタ

r ::= レジスタ
r0 | r1 | ... | r15 汎用レジスタ

整数即値

i ::= 整数即値
42 10進整数
-42 負の10進整数
0x2a 16進整数
0b101010 2進整数

整数即値は符号付き64ビット整数の範囲に収まらなければなりません。 アセンブリ中の整数即値は原則として生の機械整数であり、 ソース言語のタグ付き整数とは区別します。

命令

I ::= 命令
op オペランドを持たない命令
op a1 1個のオペランドを持つ命令
op a1, a2 2個のオペランドを持つ命令
op a1, a2, a3 3個のオペランドを持つ命令

opには、 add、load、jumpなどの命令名を指定します。 使用できる命令とオペランドの組合せは、仮想命令セットの仕様に従います。

オペランド

a ::= オペランド
r レジスタ
i 整数即値
L ラベル
i(r) ベースレジスタとオフセットによるメモリアドレス

メモリアドレス

メモリアクセスには、ベースレジスタとワード単位のオフセットを使用します。 

load  r1, 0(r2)
            load  r3, 2(r2)
            store r4, -1(r14)

例えば2(r2)は、 r2の値に2ワードを加えたアドレスを表します。

ラベル

ラベルは、命令または静的データの位置に名前を付けます。 

main:
                li    r1, 42
                jump  finish

            finish:
                halt

ラベル名は、英字またはアンダースコアで始まり、 以降に英数字、アンダースコア、ピリオドを使用できます。 

main
            loop_1
            runtime.print_int
            .L_internal

同じアセンブリ単位内で、同じラベルを複数回定義することはできません。

セクション

D ::= ディレクティブ
.text 以降をコード領域へ配置する
.data 以降を静的データ領域へ配置する

プログラムは通常、コードを置く.textセクションと、 静的な値を置く.dataセクションから構成されます。

静的データ

.word i 1ワードの整数を配置する
.word L ラベルのアドレスを1ワード配置する
.string s 文字列を配置する
.zero i 指定したワード数を0で初期化する
.align i 以降のデータ位置を指定した境界へ揃える

文字列リテラルには、ダブルクォートを使用します。 

.data

            message:
                .string "hello\n"

シンボル

.global L ラベルを他のアセンブリ単位へ公開する
.extern L 別のアセンブリ単位で定義されるラベルを参照する
.entry L プログラムの開始位置を指定する

単一ファイルだけを扱う段階では、 .globalと.externを省略できます。 分割コンパイルとリンクを導入した段階で使用します。

コメント

セミコロンから行末まではコメントとして無視します。 

li   r1, 42      ; r1へ42を格納する
            halt             ; 実行を終了する

疑似命令

疑似命令は、アセンブラによって一つ以上の基本命令へ展開されます。

nop mov r0, r0
neg rd, rs sub rd, r0, rs
subi rd, rs, i addi rd, rs, -i
call L jal r15, L
callr rs jalr r15, rs
ret jalr r0, r15
push rs スタックポインタを減らして値を書き込む
pop rd 値を読み出してスタックポインタを増やす

アセンブリプログラムの例

.text
            .global main
            .entry main

            main:
                li    r1, 40
                li    r2, 2
                add   r1, r1, r2
                call  runtime_print_int

                li    r1, 0
                trap  0

            .data

            message:
                .string "result\n"

アセンブラの処理

アセンブラは、概ね次の順序でアセンブリを処理します。

  1. アセンブリテキストを字句解析する
  2. 命令、ラベル、ディレクティブを構文解析する
  3. 疑似命令を基本命令へ展開する
  4. コードラベルとデータラベルの位置を計算する
  5. ラベル参照を具体的なアドレスへ置き換える
  6. 実行可能命令列と静的データを生成する

エラー

アセンブラは、少なくとも次の場合にエラーを報告します。

  • 存在しない命令名を使用した場合
  • オペランドの個数または種類が正しくない場合
  • 存在しないレジスタを指定した場合
  • 同じラベルを複数回定義した場合
  • 未定義のラベルを参照した場合
  • 整数即値が64ビットの範囲を超えた場合
  • コード領域にデータを配置した場合
  • データ領域に命令を配置した場合

実行可能形式

アセンブラは、アセンブリテキストから仮想CPUが読み込める実行可能形式を生成します。 実行可能形式には、命令列、静的データ、エントリポイントを格納します。

executable 実行可能形式
code 実行する命令列
data 静的データ
entry 実行開始位置

命令列

命令列は、アセンブラによってラベルが解決された基本命令の配列です。 疑似命令、ラベル定義、コメントは残りません。 

code[0] = Li (1, 40)
            code[1] = Li (2, 2)
            code[2] = Add (1, 1, 2)
            code[3] = Trap 1
            code[4] = Halt

ジャンプ先や関数のコードアドレスは、命令列中の位置で表します。 

loop:
                addi  r1, r1, -1
                brnz  r1, loop

上のコードは、概念的に次の命令列になります。

code[0] = AddI (1, 1, -1)
            code[1] = BranchNonZero (1, 0)

静的データ

静的データには、文字列リテラル、定数ブロック、 関数コードへの参照などを格納します。 

.data

            message:
                .string "hello"

            pair:
                .word 3
                .word 5

データラベルは、静的データ領域内の位置へ解決されます。 コード中ではla命令を使って、そのアドレスを取得します。 

la r1, message

エントリポイント

エントリポイントは、仮想CPUが最初に実行する命令の位置です。 アセンブリでは.entryディレクティブによって指定します。 

.entry main

            main:
                li    r1, 0
                halt

.entryがない場合は、mainラベルを使用します。 mainも存在しない場合は、アセンブル時にエラーとします。

OCamlでの表現

基本仕様では、命令をビット列へ符号化せず、 OCamlのデータ型として保持します。 

type executable = {
            code : instruction array;
            data : int64 array;
            entry : int;
            }

仮想CPUは、この値を直接受け取って実行します。 固定長のバイトコードや機械語への符号化は発展仕様とします。

ロード

仮想CPUは、実行開始時に実行可能形式を次のように読み込みます。

  1. codeを命令領域へ設定する
  2. dataをメモリの静的データ領域へ配置する
  3. pcをentryへ設定する
  4. レジスタ、ヒープ、スタックを初期化する
  5. 命令の実行を開始する

分割コンパイル

単一ファイルを扱う基本仕様では、 すべてのラベルをアセンブラが解決してから実行可能形式を生成します。

分割コンパイルでは、各ファイルからオブジェクト形式を生成し、 リンカが複数のオブジェクトを一つの実行可能形式へ結合します。

symbols 発展　定義されたシンボル
imports 発展　外部から参照するシンボル
exports 発展　外部へ公開するシンボル
relocations 発展　リンク時に修正するアドレス

形式の検査

仮想CPUは実行前に、少なくとも次の条件を検査します。

  • エントリポイントが命令列の範囲内にあること
  • 命令中のレジスタ番号がr0からr15の範囲内にあること
  • 直接ジャンプ先が命令列の範囲内にあること
  • 静的データがメモリに収まること
  • 命令とオペランドの組合せが正しいこと

発展：命令の符号化

発展仕様では、各命令を整数やバイト列へ符号化できます。 この場合も、命令の意味とアセンブリ構文は基本仕様と共通です。

命令の符号化を導入する場合は、命令コード、レジスタ番号、 即値、アドレスのビット配置を別途定義します。

ランタイムAPI

ランタイムAPIは、生成コードから利用する処理を定義します。 引数はr1から順に渡し、戻り値はr1で受け取ります。

プログラムの終了

runtime_exit r1の終了コードでプログラムを終了する
runtime_abort 実行時エラーとしてプログラムを終了する

メモリ管理

runtime_alloc r1ワードのブロックを確保し、そのポインタを返す
runtime_gc 発展　ガベージコレクションを実行する

整数

runtime_print_int r1の整数を出力する
runtime_int_to_string r1の整数を文字列へ変換する
runtime_string_to_int r1の文字列を整数へ変換する

浮動小数点数

runtime_float_add r1とr2の浮動小数点数を加算する
runtime_float_sub r1からr2を減算する
runtime_float_mul r1とr2の浮動小数点数を乗算する
runtime_float_div r1をr2で除算する
runtime_print_float r1の浮動小数点数を出力する
runtime_float_to_string r1の浮動小数点数を文字列へ変換する
runtime_string_to_float r1の文字列を浮動小数点数へ変換する

文字と文字列

runtime_print_char r1の文字を出力する
runtime_read_char 1文字を読み込んで返す
runtime_print_string r1の文字列を出力する
runtime_read_line 1行を読み込んで文字列として返す
runtime_string_length r1の文字列の長さを返す
runtime_string_get r1の文字列からr2番目の文字を返す
runtime_string_concat r1とr2の文字列を連結する
runtime_string_equal r1とr2の文字列を比較する

構造的比較

runtime_equal r1とr2を構造的に比較する
runtime_compare r1とr2の順序を比較する

関数値を含む値に構造的比較を適用した場合は、 Invalid_argument例外を送出します。

実行時エラー

runtime_division_by_zero ゼロ除算を報告する
runtime_index_out_of_bounds 文字列または配列の範囲外アクセスを報告する
runtime_match_failure どのパターンにも一致しなかったことを報告する
runtime_out_of_memory メモリ不足を報告する
runtime_invalid_argument 不正な引数を報告する

配列

runtime_array_make 発展　長さr1、初期値r2の配列を作成する
runtime_array_length 発展　r1の配列の長さを返す
runtime_array_get 発展　r1の配列からr2番目の要素を返す
runtime_array_set 発展　r1の配列のr2番目へr3を書き込む

例外

runtime_raise 発展　r1の例外を送出する
runtime_push_handler 発展　例外ハンドラを登録する
runtime_pop_handler 発展　現在の例外ハンドラを解除する

継続とエフェクト

runtime_perform 発展　r1のエフェクトを実行する
runtime_continue 発展　r1の継続をr2の値で再開する
runtime_discontinue 発展　r1の継続へr2の例外を送出する

trapとの対応

OCamlで実装されたホスト処理が必要なランタイム関数は、 内部でtrap命令を使用します。

trap 0 プログラムの終了
trap 1 整数の出力
trap 2 文字の出力
trap 3 文字の入力
trap 4 文字列の出力
trap 5 1行の入力
trap 6 メモリの確保
trap 7 実行時エラーの報告

コンパイラは通常、trapを直接生成せず、 対応するランタイム関数を呼び出します。
