コア中間表現

型検査が完了した抽象構文木を、後続のK正規化とクロージャ変換で扱いやすい コア中間表現へ変換します。 この段階では、派生構文を基本構文へ変換し、パターンマッチを明示的な分岐へ変換します。 また、リスト、レコード、ヴァリアント、配列、参照などのデータ構造を、 タグ付きブロックとプリミティブ演算によって統一して表します。

  • 型付き抽象構文木
    ↓ 脱糖、名前解決結果の反映、データ表現の変換
  • コアAST
    ↓ パターンマッチのコンパイル
  • コア中間表現

コア中間表現の構文

コア中間表現の式を e、 定数を c、 変数を x、 プリミティブ演算を op で表します。

プログラムと大域宣言の構文

コア中間表現におけるプログラムは、大域宣言の列と、 プログラム開始時に評価する本体式から構成されます。 大域宣言を d、 プログラムを P で表します。

構文 名称 説明
P ::= d1 ... dn in e プログラム 大域宣言 d1から dnを順番に初期化し、 本体式 eを評価する
d ::= let x = e 大域値定義 式 eを評価し、その結果を大域変数 xへ束縛する
d ::= let rec f1 x11 ... x1m₁ = e1 and ... and fn xn1 ... xnmₙ = en 大域再帰関数定義 一つ以上の相互再帰関数を大域的に定義する
d ::= external f = name 外部関数宣言 大域識別子 fを、ランタイムまたは外部環境の関数 nameへ対応付ける

宣言の変換

let x1 = E1
...

プリミティブ演算

プリミティブ演算は、通常の関数適用とは区別されます。 各演算の引数は左から右へ評価されます。 演算結果の型は型付き抽象構文木の型情報によって確定しています。

分類 プリミティブ演算 説明
整数算術 int_neg、 int_add、 int_sub、 int_mul、 int_div、 int_mod 整数の符号反転、加算、減算、乗算、除算、剰余
整数ビット演算 int_not、 int_and、 int_or、 int_xor、 int_shift_left、 int_shift_right 整数に対するビット演算とシフト演算
浮動小数点算術 float_neg、 float_add、 float_sub、 float_mul、 float_div 浮動小数点数の符号反転と四則演算
比較 eq、 ne、 lt、 le、 gt、 ge 等値比較および順序比較。 適用できる型は型検査によって制限される
文字変換 char_code、 char_of_code 文字と文字コードを相互に変換する
文字列 string_length、 string_get、 string_concat 文字列の長さ、要素の取得、連結
配列 array_make、 array_length、 array_get、 array_set 配列の作成、長さ、要素の読み出し、要素への書き込み
変換 int_of_float、 float_of_int 整数と浮動小数点数を相互に変換する

型付き抽象構文木の各構文を、次の規則によってコアASTへ変換します。 変換関数を C⟦e⟧ と表します。 変数とコンストラクタの名前は、この変換より前に一意な識別子へ解決されているものとします。

型付き抽象構文木 コアAST 説明

x x 名前解決済みの変数をそのまま残す

パターンマッチコンパイル

コアASTに一時的に残したパターンマッチを、条件分岐、 switch、ブロックのタグ検査、フィールド読み出し、 および局所変数への束縛へ変換します。 変換後のコア中間表現には、パターンおよび match式を残しません。

パターンマッチコンパイルの定義

パターン pによる値 vの検査を、次の変換関数で表します。

記法 意味
P⟦ v, p, S, F ⟧ 値 vをパターン pと照合する。 照合に成功した場合は成功式 Sを評価し、 失敗した場合は失敗式 Fを評価する。 パターンに変数が含まれる場合、 その変数は成功式 Sの中だけで有効になる

Sと Fは、コア中間表現の式です。 変換関数 P自体はコンパイラ内部の定義であり、 変換後のコア中間表現には現れません。

個別のパターンの変換

パターン 変換結果 説明
_ S 被検査値を検査せず、そのまま成功式を評価する
x let x = v in S 被検査値を変数 xへ束縛し、成功式を評価する
c if eq(v, c) then S else F 被検査値と定数 cを比較する。 等しい場合は成功式を、異なる場合は失敗式を評価する
p as x let x = v in P⟦ v, p, S, F ⟧ 被検査値全体を xへ束縛してから、 同じ値をパターン pと照合する
p1 | p2 P⟦ v, p1, S, P⟦ v, p2, S, F ⟧⟧ 最初に p1を試し、 失敗した場合に p2を試す。 両方の選択肢は、同じ名前と型の変数を束縛しなければならない
(p1, ... , pn) let x1 = field 0 v in ... let xn = field n - 1 v in P⟦ x1, p1, ... P⟦ xn, pn, S, F ⟧ ... , F ⟧ タプルの各フィールドを一度だけ読み出し、 左から右へ対応する部分パターンと照合する。 いずれかの部分パターンが失敗した場合は Fを評価する
{ l1 = p1; ... ; ln = pn } let x1 = field index(l1) v in ... let xn = field index(ln) v in P⟦ x1, p1, ... P⟦ xn, pn, S, F ⟧ ... , F ⟧ 各フィールド名を型定義で確定したフィールド番号へ変換する。 各フィールドを一度だけ読み出し、対応する部分パターンと照合する
K if eq(v, constructor_index(K)) then S else F 引数を持たないコンストラクタを、 型定義で確定した定数コンストラクタ番号と比較する
K p1 ... pn if eq(tag v, constructor_tag(K)) then
let x1 = field 0 v in ... let xn = field n - 1 v in P⟦ x1, p1, ... P⟦ xn, pn, S, F ⟧ ... , F ⟧
else F 		先にブロックのタグを検査する。 タグが一致した場合だけフィールドを読み出し、 各部分パターンと左から右へ照合する
[] if eq(v, nil_index) then S else F 被検査値を空リストの定数コンストラクタ番号と比較する
p1 :: p2 if eq(tag v, cons_tag) then
let x1 = field 0 v in let x2 = field 1 v in P⟦ x1, p1, P⟦ x2, p2, S, F ⟧, F ⟧
else F 		consのタグを検査し、先頭要素と残りのリストを読み出す。 先頭のパターンに成功した場合だけ、残りのリストのパターンを検査する

複数の分岐の変換

パターンマッチの各分岐は、ソースプログラムに記述された順序で試します。 分岐列の変換を Rで表します。

変換対象 変換結果 説明
分岐がない場合 match_failure() どのパターンにも一致しなかったため、 パターンマッチ失敗を表すプリミティブ演算を実行する
p -> e | r2 | ... | rn P⟦ v, p, C⟦e⟧, R⟦ v, r2, ... , rn ⟧⟧ 最初のパターンに成功した場合は、その分岐本体を評価する。 失敗した場合は、残りの分岐を順番に試す
p when g -> e | r2 | ... | rn P⟦ v, p, if C⟦g⟧ then C⟦e⟧ else R⟦ v, r2, ... , rn ⟧, R⟦ v, r2, ... , rn ⟧⟧ パターンに成功した後でガード式を評価する。 ガード式が偽の場合は、その分岐に失敗したものとして次の分岐を試す

match式全体の変換

コアAST 変換後のコア中間表現 説明
match e with r1 | ... | rn let v = C⟦e⟧ in R⟦ v, r1, ... , rn ⟧ 被検査式を新しい変数 vへ一度だけ束縛する。 その後、同じ値に対して各分岐を記述順に試す

変換例

次のリストに対するパターンマッチを変換します。

match xs with
| [] -> 0
| x :: _ -> x

単純な変換結果は次のようになります。

let scrutinee = xs in
if eq(scrutinee, nil_index) then
    0
else
    if eq(tag scrutinee, cons_tag) then
        let head = field 0 scrutinee in
        let tail = field 1 scrutinee in
        let x = head in
        x
    else
        match_failure()

変数 tailはワイルドカードに対応するため、実際のコンパイラでは field 1の読み出し自体を省略できます。 その場合、最適化後の結果は次のようになります。 

let scrutinee = xs in
if eq(scrutinee, nil_index) then
    0
else
    if eq(tag scrutinee, cons_tag) then
        let x = field 0 scrutinee in
        x
    else
        match_failure()

switchを使用する変換

同じ値に対するコンストラクタタグの検査が複数続く場合は、 複数の条件分岐を一つの switchへまとめます。 

match tree with
| Leaf x -> x
| Node (left, right) -> sum left right

各コンストラクタのタグを検査する変換結果は次のようになります。

let scrutinee = tree in
switch tag scrutinee with
| leaf_tag ->
    let x = field 0 scrutinee in
    x
| node_tag ->
    let left = field 0 scrutinee in
    let right = field 1 scrutinee in
    sum left right
| default ->
    match_failure()

変換後に成立する条件

  • 被検査式は一度だけ評価され、その結果は新しい変数へ束縛されている
  • 各分岐はソースプログラムに記述された順序で試される
  • 変数パターンによる束縛は、その分岐のガード式と本体だけで有効である
  • ガード式は、対応するパターンの検査と変数束縛に成功した後でだけ評価される
  • ブロックのフィールドは、コンストラクタタグの一致を確認した後で読み出される
  • タプルとレコードの部分パターンは左から右へ検査される
  • いずれかの部分パターンが失敗した場合は、その分岐全体が失敗する
  • どの分岐にも一致しない可能性がある場合は、最後にmatch_failure()が生成される
  • 網羅性検査によってすべての場合が覆われていると証明できる場合は、到達不能なmatch_failure()を省略できる
  • 変換後のコア中間表現には、match、パターン、ガード付き分岐を残さない

実装上の補足

上の規則は、各分岐を上から順番に試す単純な変換を定義しています。 この方法は意味が明確で実装も容易ですが、複数の分岐で同じタグ検査や フィールド読み出しを繰り返すことがあります。

実装では、複数のパターンを行列としてまとめて解析する パターン行列法を使用できます。 パターン行列法では、同じ被検査値に対するコンストラクタ検査を共有し、 一つの switchへまとめます。 ただし、どの方法を使用しても、変換結果はこの節で定義した 条件分岐、タグ分岐、フィールド読み出し、局所変数束縛だけで構成されます。
