低水準中間表現

クロージャ中間表現にデータ表現の具体化を行い、 クロージャ、組、レコード、ヴァリアントなどを、 ヒープ確保とメモリ操作で表します。

  • クロージャ中間表現
    ↓ データ表現の具体化
  • 低水準中間表現

低水準化の規則

L[e]は、 クロージャ中間表現の式eを 低水準中間表現へ変換した結果を表します。

変換中に文字列、浮動小数点数、定数ブロックなどが現れた場合は、 新しいラベルを生成し、対応する静的データをプログラムへ追加します。

プログラム全体の変換

クロージャ中間表現 低水準中間表現
F1 ... Fn; e D1 ... Dm; L[F1] ... L[Fn]; L[e]

D1から Dmは、 低水準化の途中で生成された静的データです。

関数定義の変換

クロージャ中間表現 低水準中間表現
function f (closure, x1, ... , xn) = e function f (closure, x1, ... , xn) =
let z1 = load closure 1 in
...
let zm = load closure m in
L[e]
function f (x1, ... , xn) = e function f (x1, ... , xn) = L[e]

第1の形式はクロージャを通して呼び出される関数、 第2の形式は自由変数を持たず直接呼び出される関数です。

データ表現の具体化

クロージャ中間表現では、ブロックやクロージャは抽象的な操作として表されていました。 

block k (x1, ..., xn)
make_closure f [x1; ...; xn]
apply_closure f [x1; ...; xn]

低水準化では、これらをヒープ確保、メモリの読み書き、 直接または間接の関数呼出しへ変換します。

値の分類

低水準中間表現では、すべての値を64ビットの1ワードとして扱います。 値は、即値またはヒープ上のブロックへのポインタです。

値 低水準での表現
int タグ付き整数
bool タグ付き定数
unit タグ付き定数
char 文字コードを格納したタグ付き整数
引数を持たないコンストラクタ タグ付き定数
組、レコード、リスト、参照 ヒープブロックへのポインタ
引数を持つコンストラクタ ヒープブロックへのポインタ
クロージャ ヒープブロックへのポインタ
string 静的領域またはヒープ上の文字列へのポインタ
float 浮動小数点数を格納したヒープブロックへのポインタ
配列 発展　ヒープ上の可変長ブロックへのポインタ

整数の具体化

ソース言語の整数nは、次のタグ付き整数へ変換します。 

(n << 1) | 1

整数定数は、低水準中間表現の即値へ変換します。

42
    ↓
integer 85

加算と減算では、タグを考慮して結果を補正します。 乗算、除算、剰余では、演算前にタグを取り除き、 演算後に再びタグを付けます。

ヒープブロック

ヒープ上の値は、ヘッダと0個以上のフィールドからなるブロックとして表します。 

             値が指す位置
                  |
                  v
+--------+---------+---------+-----+
| header | field 0 | field 1 | ... |
+--------+---------+---------+-----+

ポインタは第1フィールドの位置を指します。 ヘッダは、その1ワード前に置きます。

ヘッダの情報 用途
サイズ フィールド数
タグ ブロックの種類またはコンストラクタ番号
GC情報 発展　生存確認や走査に使用する情報

ブロックの作成

クロージャ中間表現の次の式を考えます。

block k (x1, ..., xn)

低水準中間表現では、概念的に次のように変換します。

let base = alloc (n + 1) in
store base 0 (make_header k n);
store base 1 x1;
...
store base n xn;
address_add base 1

allocが返すアドレスはヘッダを指します。 式の結果としては、第1フィールドを指すポインタを返します。

フィールドの読み出し

クロージャ中間表現の次の式を考えます。

field i x

低水準中間表現では、次のメモリ読み出しへ変換します。

load x i

xは第1フィールドを指しているため、 フィールド0はオフセット0、フィールド1はオフセット1にあります。

フィールドへの書き込み

クロージャ中間表現の次の式を考えます。

setfield i x y

低水準中間表現では、次のメモリ書き込みへ変換します。

store x i y

書き込みの結果は単位値です。 不変なブロックに対するstoreは、コンパイラが生成しないものとします。

タグの読み出し

クロージャ中間表現の次の式を考えます。

tag x

ヘッダはポインタの1ワード前にあるため、次のように変換します。 

let header = load x (-1) in
header_tag header

header_tagは、ヘッダからタグ部分を取り出す低水準演算です。

組とレコード

組とレコードは、タグ0のブロックとして表します。 フィールドの順序はコンパイル時に固定します。 

(x, y)
    ↓
block 0 (x, y)
{ name = x; age = y }
    ↓
block 0 (x, y)

レコードのフィールド名は低水準中間表現には残りません。 フィールド名は整数オフセットへ変換されます。

ヴァリアント

引数を持たないコンストラクタはタグ付き定数として表します。 

None
    ↓
integer 1

引数を持つコンストラクタは、コンストラクタ番号をタグとするブロックとして表します。 

Some x
    ↓
block some_tag (x)

パターンマッチは、即値の比較またはブロックヘッダのタグ検査として表されます。

リスト

空リストは引数を持たないコンストラクタとして表します。 consセルは2フィールドのブロックとして表します。 

[]
    ↓
empty_list_value
x :: xs
    ↓
block cons_tag (x, xs)
フィールド 内容
0 先頭要素
1 残りのリスト

参照

参照は、1フィールドの可変ブロックとして表します。 

ref x
    ↓
block reference_tag (x)
!r
    ↓
load r 0
r := x
    ↓
store r 0 x

文字列

文字列リテラルは静的データ領域へ配置し、 そのアドレスを低水準中間表現の値として使用します。 

"hello"
    ↓
address_of string_0

実行時に生成される文字列は、ランタイムがヒープ上に確保します。 文字列の連結、長さの取得、文字の取得はランタイム関数呼出しへ変換します。

操作 低水準化後
s1 ^ s2 runtime_call runtime_string_concat (s1, s2)
String.length s runtime_call runtime_string_length (s)
String.get s i runtime_call runtime_string_get (s, i)

浮動小数点数

基本仕様では、浮動小数点数を1フィールドの専用ブロックへ格納します。 

3.14
    ↓
address_of float_constant_0

浮動小数点演算は、ランタイム関数呼出しへ変換します。 

x +. y
    ↓
runtime_call runtime_float_add (x, y)

クロージャ

クロージャは、コードアドレスと自由変数を持つブロックとして表します。 

make_closure f [x1; ...; xn]

低水準中間表現では、概念的に次のように変換します。

let base = alloc (n + 2) in
store base 0 (make_header closure_tag (n + 1));
store base 1 (address_of f);
store base 2 x1;
...
store base (n + 1) xn;
address_add base 1

クロージャポインタから見たフィールド配置は次のとおりです。

オフセット 内容
-1 ヘッダ
0 コードアドレス
1以降 自由変数

直接呼出し

クロージャ中間表現の次の式を考えます。

apply_direct f [x1; ...; xn]

低水準中間表現では、次の直接呼出しへ変換します。

call f (x1, ..., xn)

呼出し先がコンパイル時に確定しているため、 クロージャからコードアドレスを読み出す必要はありません。

クロージャ呼出し

クロージャ中間表現の次の式を考えます。

apply_closure f [x1; ...; xn]

低水準中間表現では、次のように変換します。

let code = load f 0 in
call_indirect code (f, x1, ..., xn)

クロージャ自身を第1引数として渡します。 呼出された関数は、クロージャから自由変数を読み出します。 

let x1 = load closure 1 in
let x2 = load closure 2 in
...

部分適用

部分適用は、与えられた引数を自由変数として保存する補助クロージャへ変換します。 

let add x y = x + y in
add 3

概念的には次の補助関数とクロージャを生成します。

function partial_add(closure, y):
    let x = load closure 1 in
    call add (x, y)

make_closure partial_add [3]

部分適用のための補助関数は、クロージャ変換または低水準化の段階で生成します。

ランタイム関数呼出し

低水準中間表現から利用するランタイム関数は、 runtime_callで表します。 

runtime_call runtime_alloc (size)
runtime_call runtime_print_int (x)
runtime_call runtime_equal (x, y)

runtime_callは、通常の関数呼出しとは区別して保持します。 これにより、呼出し規約や外部処理を命令選択時に適切に処理できます。

低水準化の結果

  • 組、レコード、ヴァリアント、リスト、参照がヒープブロックへ変換される
  • クロージャがコードアドレスと自由変数を持つブロックへ変換される
  • フィールド操作がメモリのロードとストアへ変換される
  • 整数などの実行時表現が具体化される
  • 文字列、浮動小数点数、構造的比較などがランタイム関数呼出しになる
  • 関数呼出しが直接呼出しまたは間接呼出しとして明示される
  • 静的な文字列、浮動小数点数、定数ブロックが静的データとして分離される

次の仮想レジスタ中間表現への変換では、 低水準演算を仮想命令セットの命令へ変換し、 条件分岐と関数呼出しを基本ブロックとして配置します。
