クロージャ中間表現

K正規形に自由変数解析とクロージャ変換を行い、 局所関数と無名関数をトップレベル関数定義へ移動します。 自由変数を持つ関数については、 関数のコード位置と自由変数を保持するクロージャを明示します。

  • K正規形
  • ↓ 自由変数解析・クロージャ変換
  • クロージャ中間表現

クロージャ変換後は、 funおよび局所的な let recを式として残しません。 すべての関数本体はトップレベル関数定義へ移され、 関数適用は直接呼出しまたはクロージャ呼出しへ分類されます。

プログラムの構文

クロージャ中間表現のプログラムは、 外部関数宣言、トップレベル関数定義、大域値定義、 およびプログラム本体から構成されます。 プログラムを P、 外部関数宣言を X、 トップレベル関数定義を F、 大域値定義を G、 式を e で表します。

構文 名称 説明
P ::= X1 ... Xl F1 ... Fm G1 ... Gn in e プログラム 外部関数宣言、トップレベル関数定義、大域値定義、 およびプログラム本体をまとめたもの

外部関数宣言の構文

構文 名称 説明
X ::= external f = name 外部関数宣言 内部識別子 fを、ランタイムまたは外部環境の関数 nameへ対応付ける

トップレベル関数定義の構文

クロージャ中間表現では、すべての関数本体をトップレベルへ移動します。 各関数定義には、コードラベル、通常の仮引数、 クロージャ環境から取得する自由変数、および関数本体を記録します。

構文 名称 説明
F ::= function l ( x1, ... , xn ; z1, ... , zm ) = e トップレベル関数定義 コードラベル lを持つ関数を定義する。 x1から xnは通常の仮引数、 z1から zmはクロージャ環境から受け取る自由変数である

自由変数を持たない関数では、 セミコロンより後ろの自由変数列を空にします。 

function add(x, y; ) =
    int_add(x, y)

自由変数を持つ関数では、 クロージャ内の各要素と自由変数列を同じ順序で対応付けます。 

function add_x(y; x) =
    int_add(x, y)

大域値定義の構文

構文 名称 説明
G ::= let x = e 大域値定義 式 eを評価し、その結果を大域変数 xへ束縛する

K正規形に存在した大域再帰関数定義は、 トップレベル関数定義と、必要に応じて生成する大域クロージャ値へ分解します。 そのため、クロージャ中間表現には大域的な let recを残しません。

式の構文

定数を c、 変数を x、 コードラベルを l、 プリミティブ演算を op、 ブロックタグまたは switchの比較値を k で表します。

構文 名称 説明
e ::= c 定数 整数、浮動小数点数、真偽値、文字、文字列、 unitなどの定数
e ::= x 変数 局所変数または大域変数の参照
e ::= op( x1, ... , xn) プリミティブ演算 変数をオペランドとしてプリミティブ演算を実行する
e ::= if x then e1 else e2 条件分岐 xが真なら e1を、偽なら e2を評価する
e ::= let x = e1 in e2 局所定義 e1の結果を xへ束縛し、 e2を評価する
e ::= make_closure l [ z1; ... ; zm] クロージャの作成 コードラベル lと自由変数 z1から zmを保持するクロージャを作成する
e ::= apply_direct l [ x1; ... ; xn ; z1; ... ; zm] 関数の直接呼出し コンパイル時に確定したコードラベル lを直接呼び出す。 通常の実引数に加えて、必要な自由変数を明示的に渡す
e ::= apply_closure f [ x1; ... ; xn] クロージャ呼出し 変数 fが保持するクロージャからコード位置と環境を取得し、 通常の実引数とともに呼び出す
e ::= block k ( x1, ... , xn) ブロックの作成 タグ kと指定されたフィールドを持つブロックを作成する
e ::= field i x フィールドの読み出し xが表すブロックの i番目のフィールドを読み出す
e ::= setfield i x y フィールドへの書き込み xが表す可変ブロックの i番目のフィールドへ yを書き込み、 unitを返す
e ::= tag x タグの読み出し xが表すブロックのタグを読み出す
e ::= switch x with k1 -> e1 | ... | kn -> en | default -> ed 整数またはタグによる分岐 xの値と一致する分岐を評価する。 一致する値がない場合は省略可能な default分岐を評価する
e ::= raise x 例外の送出 セルフホスト後変数xが表す例外値を送出する
e ::= try e1 with x -> e2 例外処理 セルフホスト後 e1から送出された例外を xへ束縛し、 e2で処理する
e ::= perform x エフェクトの実行 セルフホスト後変数xが表すエフェクトを実行する

型情報

表では簡潔さのため型を省略していますが、 実装上は大域変数、局所変数、関数の仮引数、自由変数、 関数の戻り値、およびクロージャ値の型を保持します。

トップレベル関数定義には、通常の仮引数の型、 自由変数の型、および戻り値の型を記録します。 クロージャ型には少なくとも、呼出し時に要求される引数型と戻り値型を保持します。

クロージャの論理的な構造

クロージャは、関数のコード位置と、その関数が必要とする自由変数をまとめた値です。 クロージャ中間表現では、クロージャの具体的なメモリ配置はまだ決定しません。 

closure {
    code = function_label;
    environment = [free_variable_1; ...; free_variable_n];
}

後続の低水準化では、 make_closureをヒープ上のブロック確保とフィールド書込みへ変換し、 apply_closureをコード位置の読み出しと間接呼出しへ変換します。

自由変数

式の中で参照される変数のうち、 その式の内部で束縛されていない変数を自由変数と呼びます。 式 eの自由変数集合を FV⟦e⟧ と表します。

関数本体 eからクロージャへ保存する自由変数は、 FV⟦e⟧ から、その関数の仮引数、関数自身の名前、 同じ相互再帰関数群に属する関数名を取り除いたものです。

クロージャ変換

K正規形の式 eのクロージャ変換を C⟦e⟧ と表します。 変換は式を返すだけでなく、 新しく生成したトップレベル関数定義をプログラムへ追加します。

変換中は、直接呼び出せることが分かっている関数と、 各関数に必要な自由変数の情報を環境に保持します。

無名関数の変換

次の無名関数を考えます。 関数本体 eの自由変数を、 z1から zmとします。 

fun x1 ... xn -> e

新しいコードラベル lを生成し、 次のトップレベル関数定義を追加します。 

function l(x1, ..., xn; z1, ..., zm) =
    C⟦e⟧

元の無名関数の位置には、自由変数を保存するクロージャ作成を置きます。 

make_closure l [z1; ...; zm]

この段階では、自由変数の読出しを fieldとして関数本体へ挿入する必要はありません。 トップレベル関数定義の自由変数列が、 クロージャ環境から取得する値を論理的に表します。 具体的な環境ポインタとフィールド読出しは後続の低水準化で導入します。

局所再帰関数の変換

次の局所再帰関数を考えます。 

let rec f x1 ... xn = e1 in e2

関数本体について、関数自身 fと仮引数を除いた自由変数を求めます。 その自由変数を z1から zmとします。

新しいコードラベル lを生成し、 次のトップレベル関数定義を追加します。 

function l(x1, ..., xn; z1, ..., zm) =
    C⟦e1⟧

関数 fが後続式 e2で値として必要な場合は、 元の let recを次の局所定義へ置き換えます。 

let f = make_closure l [z1; ...; zm] in
C⟦e2⟧

関数 fが既知の直接呼出しでしか使用されず、 クロージャ値として参照されない場合は、 make_closureを省略できます。 

C⟦e2⟧

この場合、 e2に含まれる fへの呼出しは、 コードラベル lへの apply_directへ変換します。

再帰呼出し

再帰関数本体から同じ関数を呼ぶ場合も、 呼出し先のコードラベルは確定しています。 必要な自由変数を現在の関数が保持しているため、 自己再帰呼出しは直接呼出しにできます。 

let rec loop n =
    if is_zero(n) then
        0
    else
        loop (pred n)
in
loop x

概念的には次のように変換します。 

function loop_code(n; ) =
    if is_zero(n) then
        0
    else
        let next = pred(n) in
        apply_direct loop_code [next; ]

apply_direct loop_code [x; ]

自由変数を持つ関数の直接呼出し

自由変数を持つ関数でも、 呼出し先のコードラベルと必要な自由変数が呼出し位置で確定している場合は、 クロージャを経由せず直接呼び出せます。 

let x = 10 in
let rec add_x y =
    int_add(x, y)
in
add_x z

概念的には次のように変換します。 

function add_x_code(y; x) =
    int_add(x, y)

apply_direct add_x_code [z; x]

ただし、 add_x自体を別の関数へ渡したり、 データ構造へ格納したり、 結果として返したりする場合は、クロージャ作成が必要です。

関数値として使用される既知関数

自由変数を持たない関数でも、 関数そのものを値として使用する場合はクロージャ値が必要です。 

let rec add x y =
    int_add(x, y)
in
add

関数本体をトップレベルへ移動し、 空の環境を持つクロージャを作成します。 

function add_code(x, y; ) =
    int_add(x, y)

make_closure add_code []

相互再帰関数の変換

相互再帰関数群は、一つの集合として解析します。 各関数の自由変数を求める際には、 同じ相互再帰関数群に属する関数名を自由変数集合から除きます。 

let rec even n =
    if is_zero(n) then
        true
    else
        let next = pred(n) in
        odd next
and odd n =
    if is_zero(n) then
        false
    else
        let next = pred(n) in
        even next
in
even x

外側の自由変数を持たず、各関数が既知の呼出し先としてだけ使用される場合は、 すべて直接呼出しにできます。 

function even_code(n; ) =
    if is_zero(n) then
        true
    else
        let next = pred(n) in
        apply_direct odd_code [next; ]

function odd_code(n; ) =
    if is_zero(n) then
        false
    else
        let next = pred(n) in
        apply_direct even_code [next; ]

apply_direct even_code [x; ]

相互再帰関数群が外側の自由変数を参照する場合は、 各トップレベル関数定義の自由変数列へ、その値を追加します。 呼出し位置から必要な自由変数が分かる場合は、 相互再帰呼出しでも直接渡せます。

相互再帰関数同士を関数値として参照する場合は、 複数のクロージャを相互参照させる初期化処理が必要になります。 この処理は通常の make_closureだけでは循環初期化を表しにくいため、 後続の低水準化で次のいずれかとして実装します。

  • 必要なクロージャ領域を先にすべて確保し、その後で各フィールドを書き込む
  • 相互再帰関数群で一つの共有環境を作り、各クロージャから共有環境を参照する
  • 相互再帰関数群全体を一つの再帰環境ブロックとして表現する

直接呼出しとクロージャ呼出し

関数適用は、呼出し先と環境がコンパイル時に確定するかどうかによって分類します。

条件 生成する呼出し 説明
コードラベルが確定し、 必要な自由変数を呼出し位置から直接渡せる apply_direct コードラベルを直接呼び出し、 通常の実引数と自由変数を明示的に渡す
関数が引数、戻り値、データ構造のフィールドなどから得られ、 呼出し先が実行時に決まる apply_closure クロージャからコード位置と環境を取得して間接的に呼び出す
コードラベルは判明しているが、 関数値そのものもプログラム内で必要になる 呼出しにはapply_directを使用できるが、 関数値が必要な位置ではmake_closureを生成する 直接呼出し可能性とクロージャ作成の必要性は別に判定する

無名関数の変換例

let make_adder =
    fun x ->
        fun y ->
            int_add(x, y)
in
make_adder

内側の関数では xが自由変数です。 二つの関数をトップレベルへ移動します。 

function add_code(y; x) =
    int_add(x, y)

function make_adder_code(x; ) =
    make_closure add_code [x]

make_closure make_adder_code []

make_adder_codeは自由変数を持ちませんが、 プログラムの結果として関数値を返すため、 空の環境を持つクロージャを作成します。

呼出しの変換例

既知の関数の直接呼出し

let rec add x y =
    int_add(x, y)
in
add a b
function add_code(x, y; ) =
    int_add(x, y)

apply_direct add_code [a; b; ]

関数引数のクロージャ呼出し

let apply =
    fun f x ->
        f x
in
apply
function apply_code(f, x; ) =
    apply_closure f [x]

make_closure apply_code []

関数 fのコード位置は、 apply_codeをコンパイルする時点では分かりません。 そのため、 f xはクロージャ呼出しになります。

大域関数の変換例

次の大域再帰関数定義を考えます。 

let rec factorial n =
    if is_zero(n) then
        1
    else
        let previous = pred(n) in
        let result = factorial previous in
        int_mul(n, result)

in
factorial input

関数本体をトップレベル関数定義へ変換し、 既知の自己再帰呼出しとプログラム本体からの呼出しを直接呼出しにします。 

function factorial_code(n; ) =
    if is_zero(n) then
        1
    else
        let previous = pred(n) in
        let result =
            apply_direct factorial_code [previous; ]
        in
        int_mul(n, result)

in
apply_direct factorial_code [input; ]

情報 内容 使用箇所

通常の仮引数 ソース関数が明示的に受け取る引数の列 呼出し規約、関数本体の変数環境
自由変数列 関数が外側のスコープから取得する値の列。 クロージャ内の配置順序もこの列によって決定する クロージャ作成、直接呼出し、環境の低水準化
関数型 引数型と戻り値型 呼出しの検証、呼出し規約、後続の低水準化

クロージャ変換で変化しないもの

  • 大域値定義と局所値定義の評価順序は変更しない
  • プリミティブ演算の種類とオペランド順序は変更しない
  • 条件分岐とswitchの分岐構造は変更しない
  • ブロックのタグ、フィールド数、フィールド順序は変更しない
  • フィールドの読出しと書込みの意味は変更しない
  • 例外送出、例外処理、エフェクト実行の制御上の意味は変更しない
  • K正規化によって明示された左から右の評価順序は保存する
  • 変数と関数の型は保存する

クロージャ変換後に成立する条件

  • すべての関数本体がトップレベル関数定義として表現されている
  • 式の中にfunが残っていない
  • 式の中に局所的なlet recが残っていない
  • 大域的なlet recがトップレベル関数定義へ変換されている
  • 各トップレベル関数定義の通常の仮引数が明示されている
  • 各トップレベル関数定義が必要とする自由変数の列が明示されている
  • クロージャへ格納する自由変数と、関数定義の自由変数列の順序が一致している
  • 関数値が必要な位置にはmake_closureが生成されている
  • コンパイル時に呼出し先と環境が確定する呼出しはapply_directになっている
  • 呼出し先が実行時に決まる呼出しはapply_closureになっている
  • apply_directには通常の実引数と必要な自由変数が明示されている
  • apply_closureの関数部分とすべての実引数が変数である
  • クロージャが不要な既知関数については、不要なmake_closureを省略できる
  • すべてのトップレベル関数定義とクロージャ値に型情報が付与されている
  • パターン、match、モジュール宣言、型宣言など、前段階で除去された構文は再導入されていない

次の変換との関係

クロージャ中間表現では、クロージャを論理的な 「コードラベルと自由変数の組」として表します。 次の低水準化では、この論理表現を具体的なヒープ上のデータへ変換します。

  • make_closureをクロージャブロックの確保と初期化へ変換する
  • apply_directを既知のコードラベルへの直接呼出しへ変換する
  • apply_closureをコード位置の読出し、環境の受渡し、間接呼出しへ変換する
  • トップレベル関数定義の自由変数列を、環境ポインタからのフィールド読出しへ変換する
  • 相互再帰クロージャが必要な場合は、確保と初期化を分離して循環参照を構築する
